# 助手类产品的商业化路径：订阅、额度、广告、交易与 API

**分类**：对话助手（横向分析）

**资料核验**：2026-09-14；比较已公开机制，不估算厂商未披露的收入占比。

## 一、产品背景

助手完成任务会消耗模型、工具、运行环境和人工支持。商业化要回答谁付钱、为什么付、按什么单位付，以及失败和重试由谁承担。公司总收入、App 月活和模型 API 调用规模不能互相代替。

旧稿用媒体 ARR、假设转化率解释厂商必然采取某种变现路径。本次删除这些推断，并将具体价格集中在单品案例和成本主文。

## 二、核心功能拆解：收费机制也是产品交互

| 机制 | 用户购买的对象 | 需要解释的交互 | 对应证据 |
|---|---|---|---|
| 订阅/席位 | 一段时间内的访问与权益 | 权益、额度、账期、续订 | 官方套餐和购买条件 |
| credits/额度 | 可消耗资源 | 不同任务折算、共享与过期 | 消耗记录与额度规则 |
| 广告 | 广告主购买触达 | 标识、选择权、回答与广告关系 | 具体地区/档位广告说明 |
| 交易服务 | 下单与履约服务带来的价值 | 购买确认、回执、售后 | 订单及归因数据 |
| API/企业用量 | 模型、工具与运行资源 | 计量单位、预算、失败归属 | 账单与调用记录 |

这是机制分类，不是五类互斥公司。以已核验的产品动作看：[Claude](claude-anthropic.md)有专业订阅与企业席位加用量；[Kimi](kimi.md)采用共享额度并区分入口频控；[豆包](doubao.md)的协议区分会员、创作额度包和存储；[千问](qwen.md)接入交易履约。这些动作都不足以单独判断主收入来源。

[ChatGPT 套餐页](https://chatgpt.com/pricing/)说明 Go 可能包括广告，只支持这一档位范围的事实；不能据此称广告商业化已验证成功，或把所有购物结果当广告。

## 三、技术方案推测：计量与任务状态必须对齐

从产品设计角度，账单系统至少需要关联用户、原始任务、模型调用、工具动作、重试和人工接管。这是本文提出的设计职责，不代表各家后台采用同一实现。

注意几个容易混淆的单位：

- **seat** 是可访问系统的席位，不是活跃人数。
- **credit** 是厂商折算单位，跨平台不天然等价。
- **action/step** 是特定规则下的操作或步骤，不一定一一对应用户任务。
- **resolution** 是合同定义的解决单位，必须说明重开和转人工规则。
- **outcome** 是被约定的结果，不应未经验证就称为“业务成功”。

按“结果”收费也可能有争议：助手创建申请单算完成，主管拒绝是否退款，设备未交付谁负责？产品合同要定义结果边界，日志要能验证这个边界。完整决策方法见 [AI 产品定价与商业化](../../02-pm-skills/cost-and-tech/ai-pricing-and-monetization.md)。

## 四、商业模式：用同一成本口径做选择

### 先区分收入与成本

以本库[虚构内部服务助手](../../02-pm-skills/practice/internal-service-adoption.md)为例，一个教学月有 1000 项去重意图，完成 840 项，全部运行与人工成本 1000 元。每项意图成本 1 元，每项完成成本约 1.19 元。这个结果没有任何对外收费，不能称 ARPU 或付费收入。

如果为它设计商业化，应该另建收入情景：席位数乘实际单价，或者符合合同的计费完成数乘结果单价，再扣退款和优惠。不能把 840 个完成全部自动记为付费解决，也不能把节省的人工时间直接记成现金收入。

### 五种路径的验证条件

| 选择 | 适用假设 | 应先证伪的风险 |
|---|---|---|
| 订阅 | 用户有重复需求，愿意付可预期月费 | 低频用户不续费，重度用户打穿预算 |
| 额度 | 任务复杂度变化大，消耗能解释 | 用户无法预测成本，共享池互相挤占 |
| 广告 | 有合适场景与广告需求 | 干扰任务、损害信任或归因不清 |
| 交易 | 能完成授权、履约及售后 | 补贴退潮后无复购，AI 增量无法分离 |
| 企业/API | 有组织采购或开发者需求 | 集成与支持成本高，实际用量不稳定 |

这些是待验证假设，不是“免费产品必须加广告”“有电商一定适合交易收费”的结论。

### 日期与单位的两项纠错

[Anthropic 官方 API 定价](https://platform.claude.com/docs/en/about-claude/pricing)取消原定 Sonnet 5 涨价，旧价表中 2/10 美元变 3/15 美元的箭头应删除，预算转链 [LLM 成本入门](../../02-pm-skills/cost-and-tech/llm-cost-101.md)。

[Atlassian 9 月 1 日公告](https://www.atlassian.com/blog/company-news/expanded-usage-based-pricing)讨论 credits、steps、resolutions 等不同计量，相关变化 **12 月 3 日生效**。9 月可以写为已宣布的计费调整，不应当作本月已执行账单。

## 五、PM 视角的启示

1. 收费单位必须对应可查的状态和证据，尤其是失败、重试、人工接管与重开。
2. 价格表需要地区、账期、额度和生效日，活动赠送不能成为长期成本假设。
3. 商业模式评审要同时呈现真实任务漏斗和全部成本。厂商未公开收入拆分时，保留未知比用媒体测算补齐更可靠。
