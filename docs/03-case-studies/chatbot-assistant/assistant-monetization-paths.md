# 助手类产品的商业化路径:订阅、广告、还是 API

**分类**:对话助手(横向合集)
**体验时间**:2026 年 7 月

> 本文只回答「助手怎么赚钱」。各家产品定位、功能矩阵与竞争叙事见 [头部通用助手的差异化定位对比](assistant-positioning-comparison.md);细节证据以同目录单品案例为准。

## 一、问题背景:规模之后,钱从哪来?

对话助手的边际成本不是趋近于零的传统软件,而是**按 token 线性增长的推理账单**。仓库内 [LLM 成本入门](../../02-pm-skills/cost-and-tech/llm-cost-101.md) 给出量级感:即便只是 DAU 10 万、渗透 30%、人均日调 5 次的问答功能,用主力档模型粗算也可能到约 **2.5 万美元/月** 量级——且这还只是 API 费,不含标注、评测与工程人力。推到数亿月活的免费对话,账单是持续的,不是活动脉冲。

国内体量把问题推到极致:QuestMobile(2026 年 3 月)口径下,豆包 App 月活约 **3.45 亿**,千问约 **1.66 亿**(DeepSeek 约 1.27 亿)。海外 ChatGPT 则是周活约 **9 亿**、App 月活破 **10 亿**量级(见 ChatGPT 案)。规模越大,「只靠情怀免费」越不可持续——但砍免费能力,又等于自废分发与网络效应。

因此 2026 年上半年,头部助手几乎同时被逼回答同一题:**免费层养规模之后,哪条变现路径能覆盖算力,又不打穿基本盘?** 答案并不唯一。把同目录案例压成一条轴:

| 产品 | 主路径(公开动作口径) | 辅路径 |
|------|----------------------|--------|
| ChatGPT | 订阅分层(Free→Go→Plus→Pro + Business/Enterprise) | 美区低价档广告 + Shopping Research 购物货币化;API |
| Claude | 订阅额度阶梯(Pro→Max) + API/企业「席位+用量」 | 公开材料几乎不见消费级广告 |
| 豆包 | 专业版订阅(68/200/500)卖额度与模型档位 | 并行探索抖音商城等交易导流 |
| 千问 | 对话入口抢淘宝/闪购等**交易履约** | 2026 上半年未见豆包式订阅主叙事 |

下文按五条路径拆「钱怎么进来」,再对照成本约束与选型逻辑。数字只引用上述案例与成本文;**媒体/投行情景测算一律标存疑**,对齐豆包文口径。

## 二、五条路径拆解:钱分别怎么进来

### 1. 订阅:把不确定的算力,卖成可预期的月费

订阅的产品语言通常不是「解锁聊天」,而是**额度、模型档位、高峰优先、Agent 长跑能力**——用户买的是稀缺算力与完成复杂任务的权利。

**ChatGPT**(核实至 2026-07 官方定价页):Free → Go($8/月,消息量约 Free 的 10 倍,仍含广告)→ Plus($20/月,GPT-5.5、Deep Research/Agent 等)→ Pro($100 或 $200/月,更高额度与 Pro 模型)。团队侧 Business 约 $25–30/席/月;Enterprise 定制(第三方估算约 $40–60/席/月,**估算口径**)。

**Claude**:Free → Pro($20/月)→ Max 5x($100)/Max 20x($200),核心卖点是用量倍数与 Cowork/Claude Code 等重度 Agent;Team/Enterprise 再叠 SSO、连接器管控与合规。Enterprise 常见结构是**低席位费 + 按 API 费率计用量**,让组织为真实消耗买单。

**豆包**:2026-06-24 专业版上线,标准/加强/高级约 **68 / 200 / 500 元**连续包月(年付有公开报道折扣);官方强调基础功能永久免费,付费买专家/办公额度与 2.1 Pro 等档位。相对国内部分约 49 元入门档,豆包起跳更高,锚点更偏生产力用户。

订阅适合:用户能感知「不够用」,且愿意为稳定体验付月费。设计上常见两招——**能力可见、额度可见**(免费也能摸到办公/Agent,但很快触顶),以及 **Pro→Max 式倍数跳档**(承认利润只来自一小撮重度用户)。失败模式:砍免费聊天伤规模;或阶梯过陡、转化极低,推理成本仍悬空;再用未经审计的「MAU×转化率」安慰自己。

### 2. 广告:用免费层现金流补贴规模

ChatGPT 在 2026 年明确走通「低价/免费档广告」:1 月确认美区 Free/Go 内测广告;5 月自助广告平台降低门槛。形态上贴近 **Shopping Research**——用户在对话里主动描述购物需求,意图信号强于传统页面曝光。逻辑是:巨量免费用户转化率有限时,广告与更细付费分层一起补现金流;同案亦提到外部测算下公司仍大幅亏损(「每赚 1 美元亏约 1.22 美元」一级,**媒体外部测算,标存疑**),这有助于理解广告化动机,但不能当作官方财报。

Claude 公开叙事几乎不做消费级广告,对照说明:**广告不是助手标配**,而是「广度优先 + 超大免费盘」下的选项。豆包侧公开动作更强调订阅与电商导流,广告是否成为主轴,案例未写成已验证事实。

风险:信任与回答公正性被质疑;广告若侵入高意图专业场景,会与「可交付协作」心智冲突。PM 若评估广告,应先问「广告库存落在哪一档用户、哪一类意图」,而不是先问「CPM 能做多高」。

### 3. 交易导流 / 履约:对话变成订单

这条路径的北星不是席位费,而是**订单、复购与生态抽成**。

**千问**是典型:2026-01 起接入淘宝闪购/支付宝/飞猪等;春节「请客/免单」把授权与支付练成习惯;5 月 11 日与淘宝全面打通,对话内选品下单、淘宝内嵌千问助手。商业命题是「需求发出的第一句话留在阿里履约闭环」,而不是先砌会员墙。春节「30 亿」投入、单日破千万单等属活动期披露,**非常态经营数据,不宜外推 GMV**。

**豆包**并行探索抖音商城导流:商品卡点击后进详情等转化数字见诸媒体,但分母与窗口不透明——豆包文已标**存疑/未证实**,本文不升格为财务事实。相对千问「推荐→下单→物流→售后」同生态闭环,豆包公开报道更偏「推荐并跳转」,履约深度不在同一层级。

适合前提:**公司自有或可控的商品/履约中台**。没有中台硬做「对话购物」,容易停在外链佣金,归因与体验都弱。指标上也不应强行对标内容型助手的人均打开次数——千问案季度人均使用约 **19.8** 次、豆包约 **54.8** 次(QuestMobile),任务型入口更低频可以成立,只要下单率与复购达标。

### 4. API:把模型能力卖给开发者与产品内嵌

API 是「按量把成本与收入对齐」的经典形态。案例中可引用的官方单价(每百万 Token,2026-07):

| 来源 | 模型 | 输入 | 输出 |
|------|------|------|------|
| ChatGPT 案例 | GPT-5.5 | $5 | $30 |
| Claude 案例 / 成本文 | Claude Sonnet 5(引导价→标准价) | $2→$3 | $10→$15 |
| Claude 案例 / 成本文 | Claude Opus 4.8 | $5 | $25 |
| 成本文对照 | gpt-5.4 / 轻量档等 | 见成本文表 | 输出多为输入 5–6 倍 |

对平台方:API 贡献可观收入(ChatGPT 案引媒体称约 **25%** 来自 API——**媒体报道口径,非官方拆表**)。对买方 PM:要按 [成本测算模板](../../02-pm-skills/cost-and-tech/llm-cost-101.md) 拆渗透率、人均调用、输入/输出 token,并预留缓存、路由、评测人力——**API 费不是全部成本**。

### 5. 企业合同:席位、合规与用量封顶

企业路径卖的是可治理性:SSO、RBAC、数据驻留、审计、连接器管控、支出上限。ChatGPT Business/Enterprise、Claude Team/Enterprise 都落在这条线上;Claude Enterprise「席位 + API 用量」尤其贴合 Agent 长跑——贵的是真实消耗,不是全员按最高档 lock-in。

企业单很大、销售周期长,但能把高价值用户的信任与预算锁进合同。与 C 端订阅的差别是:**采购决策者与重度使用者可能不是同一人**,产品要同时服务 IT 治理与业务交付物。

## 三、成本约束:为何路径选择被算力绑架

商业模式讨论若离开成本,容易变成口号。结合成本文与各案,助手变现至少受四道硬约束:

1. **输出比输入贵约 5–6 倍**。少让模型「废话」、控制 Agent 步数与高 effort 推理,比抠一点系统 Prompt 更省钱。Claude 把 Effort 做成用户旋钮、订阅用 Max 吃重度用量,本质是把算力预算产品化。
2. **中文与多轮上下文容易低估账单**。成本文提醒:中文约 1.5–2 字/token,系统 Prompt、历史与工具定义都算输入;Agent 多步调用会把「一次用户请求」打成多次模型调用。C 端「聊得越久越亏」与 B 端「席位包干被重度用户打穿」,同源。
3. **免费层 ARPU 接近零时,必须有第二条腿**。豆包文的判断可推广:3 亿月活上,极低付费渗透也能形成可观付费人数;但若免费层长期不贡献现金,订阅必须与交易/广告之一互补。ChatGPT 同时推订阅细化 + 广告,是同一财务压力下的组合拳。
4. **交易路径的边际成本不止 Token**。千问案指出:还有补贴、客服、物流协同与佣金分成。模型调用有可能被单笔交易毛利覆盖——因此可以更久维持「C 端不靠会员养活」,前提是对话真能提升 GMV 或降低获客成本,而不是只有闲聊。

媒体常把「MAU × 假设转化率」算成 ARR/GMV。豆包案对 **0.3%–3%** 付费转化情景、千问案对 MAU 乘转化估 GMV,均要求标存疑:**缺公开分母、时间窗与是否含学生/活动优惠前,只能当情景分析**。对内评审应强制写清:分母是 MAU、DAU 还是活跃提问用户;观测窗口是否含大促/免单;优惠与学生档是否计入。

## 四、商业模式对照:同一赛道,四种押注

| 问题 | 订阅为主 | 广告补免费盘 | 交易履约 | API/企业 |
|------|----------|--------------|----------|----------|
| 钱从哪来 | 用户月费 | 广告主 | 订单与生态抽成 | 开发者/企业预算 |
| 免费层干什么 | 触顶转化 | 养规模与广告库存 | 养「对话即下单」 | 试用/沙箱引流 |
| 代表动作 | 豆包 68/200/500;Claude Max;ChatGPT Plus/Pro | ChatGPT Free/Go 广告 | 千问×淘宝打通 | Claude/OpenAI API 与 Enterprise |
| 关键风险 | 转化不及预期,算力悬空 | 信任与回答公正性 | 有对话无订单,或有补贴无复购 | 价格战、开源替代、大客户议价 |
| 生态前提 | 强产品体验即可起步 | 超大免费流量 | 履约与支付中台 | 模型质量 + 平台稳定性/合规 |

ChatGPT 案引媒体:2026 年 3 月年化收入约 **250 亿美元**,约 **70%** 来自订阅(约 2000 万付费席位)、约 **25%** 来自 API——**均为媒体转引,非官方经审计拆分**;同案亦提到外部测算仍大幅亏损。本文用其理解「为何要广告化与细分层」,不把它当可对标的内部 KPI。

豆包案与千问案已给出「订阅 vs 交易」对照骨架,横向合集只需记住决策序:**先问公司有没有履约中台与分发杠杆,再问用户愿不愿意为算力付月费,最后才问广告能不能补免费盘**——顺序反了,容易做成「既要会员墙又要免费喝奶茶」的语义冲突。

选型直觉(写给要做助手商业化的 PM):

- **没有交易中台** → 优先订阅(+必要时广告),不要幻想一上来就「对话商城」。
- **有分发、要保国民级规模** → 免费聊天别设墙;收费点放在高算力 Agent/办公额度(豆包逻辑)。
- **有电商履约** → 北星可以是下单率与复购,人均打开次数低于内容型助手不一定失败(千问逻辑)。
- **做专业/企业 Agent** → 用额度与「席位+用量」表达成本,慎用打断专业心智的信息流广告(Claude 逻辑)。
- **同时卖 API 与 C 端助手** → 接受价格与体验双轨:C 端卖确定性(包月额度),API 卖弹性(按量);用缓存/路由/小模型把两边毛利都做正,而不是只加价。
- **有超级分发、公开侧坚持免费优先**(元宝逻辑) → 先把免费层成功标准写成生态跳转/文件交付/活动留存,货币化可后置到云/API/协同位;不要在定位文里预支「会员墙已验证」。详见 [元宝案例](yuanbao.md)。
- **能力口碑定锚、弱买量**(Kimi 逻辑) → 对话获客,变现重心放在 Agent/Code 等额度池与生产力付费;媒体月活波动只作情景,不作唯一 KPI。详见 [Kimi 案例](kimi.md)。

### 补位:免费优先与弱买量(与定位文六家对齐)

[定位对照文](assistant-positioning-comparison.md) 覆盖六家;上文四条主路径以 ChatGPT/Claude/豆包/千问为展开样板。另两家在公开材料里的**货币化占位**更短,但必须写清,避免「详见商业化」落空:

| 产品 | 公开可观察的变现占位 | 本文不升格为事实的部分 |
|------|----------------------|------------------------|
| **元宝** | 公开侧免费优先 + 腾讯生态分发;文件/Agent 交付作留存钩子 | 会员墙、广告主轴、云/API 分成等**经营数字未披露**——只当路径假说 |
| **Kimi** | Agent/办公能力吃额度;弱买量后更依赖愿意为生产力付费的用户 | 月活与付费转化的媒体转引口径,沿用单品文「二次来源」边界 |

对 PM:这两家提醒的是**「不转化也算成功」的免费/获客层**可以长期存在;把它们硬塞进「必须先跑通订阅 ARPU」的模板,会和公开叙事打架。

## 五、PM 视角的启示

1. **先写清「不转化也算成功」的免费层指标,再设计付费墙。** 留存、频次、生态跳转、广告库存、首单授权——都可能是免费层的正当目标。用单一付费转化率考核整个助手,会在超大 MAU 上放大乐观假设(见豆包文对审计口径的提醒)。
2. **变现点应落在用户暴露真实意图、且边际成本高的环节。** ChatGPT 购物研究吃「主动描述购买需求」;豆包吃办公 Agent/专家模式触顶;千问吃「一句话点外卖/下单」。不要在用户只想闲聊的气泡旁硬插所有变现手段。
3. **路径可以组合,但主叙事只能有一个。** ChatGPT 是订阅为主、广告/API 为辅;豆包是订阅为主、交易并行;千问是交易为主;Claude 是专业订阅 + API/企业。主叙事决定拉新文案、成功指标与组织考核——并行探索可以,左右互搏会让用户与团队同时困惑。
4. **对外引用收入与转化数字时,默认降级为「标存疑」。** 能写进 PRD 的应是官方定价、自身漏斗与成本模板;媒体 ARR、匿名「商品卡转化 3%」、活动期千万单,只适合做情景上下界,不适合当已验证事实。
5. **商业化评审把成本模板和应用漏斗放在同一页。** 先用 [LLM 成本入门](../../02-pm-skills/cost-and-tech/llm-cost-101.md) 算出免费层月度推理区间,再反推「订阅 ARPU / 广告 eCPM / 单均毛利」各自要达到多少才能打平——路径选择就会从口号变成可证伪的假设。
