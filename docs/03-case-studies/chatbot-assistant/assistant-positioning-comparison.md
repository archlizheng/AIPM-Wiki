# 通用助手的差异化定位对比

**分类**：对话助手（横向分析）

**资料核验**：2026-09-14；基于本目录已复核单品案例，不是横向实测排名。

## 一、产品背景

通用助手都在增加搜索、文件和 Agent 能力。对 PM 而言，真正可比较的问题是：用户带着什么任务进入，得到什么结果才认为完成？本文把差异化归纳为“任务完成标准、已有资产、使用成本”，这是作者的分析框架，不是厂商的唯一定位或内部战略。

不再并列不同口径的周活、App 月活和活动峰值作竞争排名；产品拥有某个功能，也不足以证明用户只在该场景选择它。

## 二、核心功能拆解：以相同任务比较

| 产品 | 本轮可观察的产品特点 | 有价值的评审任务 | 不能由此推出 |
|---|---|---|---|
| [ChatGPT](chatgpt.md) | 对话、研究、Work、Codex 等入口 | 同一材料从问答到工作产物 | 功能多就代表所有任务质量最高 |
| [Claude](claude-anthropic.md) | 对话、Cowork、Code 与组织管理 | 修正材料后延续任务并检查记忆 | 默认比竞品少幻觉、所有日志全覆盖 |
| [豆包](doubao.md) | 免费入口与会员、额度包等付费服务 | 任务触及额度后的继续与修改 | 用户规模能直接推算付费收入 |
| [千问](qwen.md) | 与淘宝商品和履约服务整合 | 从需求澄清到订单状态查询 | 所有生态收入都是 Agent 收入 |
| [Kimi](kimi.md) | 文档、表格、网站、集群等交付与共享额度 | 多份材料协同产出并核验一致性 | 更多子代理必然更可靠或更便宜 |
| [元宝](yuanbao.md) | 腾讯生态信源、文件及多模态入口 | 引用可回链并保留到最终产物 | 生态内容全部可访问或全部功能永久免费 |

这些特点可以重叠。不要把 ChatGPT 固定为“广度”、Claude 固定为“深度”，再把未做过的评测结论写进定位表。

### 可复用的比较任务卡

选择一个对目标用户真实有意义的任务，例如“三份材料生成可复核周报”。固定输入、账户可用范围和完成标准，记录：

1. **准备成本**：上传、授权、说明需求花了多久；不要只计生成时间。
2. **处理质量**：事实、来源、口径冲突、缺信息处理。
3. **产物质量**：可编辑、可导出、修改能传播、可交给同事。
4. **异常恢复**：来源失效、额度不足、取消和重试。
5. **组织适配**：权限、审计、费用与退出方式。

同一次测试只改变一个关键条件；不同付费档、不同文件或不同人工提示量不能被包装成公平性能排名。

## 三、技术方案推测

定位会影响设计取舍，但不能从市场文案推断实际架构。例如，交易助手需要订单回执，文件助手需要版本与产物管理，桌面助手需要动作验证。它们说明产品应承担的责任，不证明某家用了固定模型路由、数据库或多 Agent 调度。

更实用的系统比较是检查边界：模型能建议什么、运行时能执行什么、服务端允许什么、用户能撤回什么。方法见 [平台选型](../../02-pm-skills/cost-and-tech/agent-platform-selection-and-governance.md)。

## 四、商业模式

订阅、额度、广告、交易与 API 可同时存在。产品页能说明一个收费或合作机制，却通常不能说明真实收入占比。详细比较见 [商业化路径](assistant-monetization-paths.md)，模型价格统一到成本主文，不在此建立另一套易过时的表。

免费入口也需要成功指标：有需求的用户是否完成任务、是否复用、是否带来可归因的后续价值。不能预设所有产品都应最大化聊天频次，也不能因为某家公司有电商，就认定 AI 一定能用交易毛利覆盖成本。

## 五、PM 视角的启示

定位评审可以固定四问：

| 问题 | 可检查的输出 |
|---|---|
| 为谁解决哪个任务 | 一个清晰用户群和任务边界 |
| 怎么知道做完 | 文件、订单或来源证据，不是模糊“满意” |
| 凭什么更适合 | 有控制对照的任务结果，不是模型榜单 |
| 付出的总代价是什么 | 准备、审核、修复、费用与切换成本 |

可复用的一句话策略是：“为某类用户，在某种约束下，把某项任务做到某个可核验标准。”它比“成为最强万能助手”更容易转成需求、评测和采用计划。
