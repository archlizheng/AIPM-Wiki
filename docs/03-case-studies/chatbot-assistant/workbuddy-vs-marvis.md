# WorkBuddy 与 Marvis:腾讯的两条 Agent 产品线

**分类**:对话助手
**体验时间**:2026 年 7 月

## 一、产品背景

2026 年上半年,腾讯几乎同时把两条「能替你干活」的 Agent 产品推到台前:**WorkBuddy**(2026 年 3 月 9 日公测,腾讯云 CodeBuddy 团队)与 **Marvis / 马维斯**(2026 年 5 月 20 日正式上线,应用宝团队)。二者都不是又一个对话框聊天机器人,而是把自然语言指令落到「规划—调用工具—交付结果」的执行链路上;但落点完全不同。

| 维度 | WorkBuddy | Marvis |
|------|-----------|--------|
| 出品团队 | 腾讯云 CodeBuddy | 腾讯应用宝 |
| 上线时间 | 2026-03-09 公测 | 2026-05-20 全量(Win/Mac/Android;iOS 当时预计 6 月中) |
| 核心定位 | 免部署的 AI **办公工作台**(桌面 + IM/小程序) | **操作系统层级**个人 AI 助手 |
| 对标心智 | OpenClaw 形态的大众化/安全版;对标 Claude Cowork 一类「替你办完办公任务」 | 「贾维斯」式系统中枢:文件、应用、系统设置、跨端远控 |
| 目标用户 | 个体创业者、小微团队、HR/运营/行政等非技术岗;企业版面向组织 | 普通 PC/手机用户 + 职场人群,强调本地隐私与跨端操控 |

两条线并存,说明腾讯内部并不把「Agent」收敛成单一超级入口,而是按**工作台交付**与**系统层接管**拆开:前者卖「场景封装 + 安全可控的办公自动化」,后者卖「把整台电脑变成可对话对象」。对 PM 更有价值的,不是争论谁更像「真正的 Agent」,而是看同一家公司如何用不同权限边界、分发渠道与商业化节奏回答同一命题——「用户说一句话之后,产品到底替他做了什么、做到哪一步必须停」。

**关于规模数字(存疑)**:易观分析《中国办公智能体平台市场研究报告 2026》等二级渠道称,WorkBuddy 在桌面端办公智能体中渗透率约 15%、PC 端月访问量约 885 万等。这些数字**未经本文独立交叉核验**,口径(访问量 vs 活跃账户、调研样本 N=500 等)也不透明,下文**不作为确定事实**;腾讯财报侧曾有「以日活跃账户数计为国内最受欢迎的效率 AI 智能体服务」一类表述,亦宜作公司/财报口径理解,而非第三方审计结论。

## 二、核心功能拆解

### WorkBuddy:办公工作台——「一人指挥,专家团交付」

据官网 [codebuddy.cn/work](https://www.codebuddy.cn/work/),WorkBuddy 把自己定义为全能 AI 工作台:**免部署安装即用、多专家/多模型协同、覆盖桌面与主流 IM/小程序**。产品叙事的核心不是「聊得更聪明」,而是「给一句话,自主规划并交付完整结果」。

典型能力封装(官方场景):

| 场景包 | 面向谁 | 交付物形态 | AI 起作用的环节 |
|--------|--------|------------|-----------------|
| OPC「一人公司」 | 个体创业者、小微负责人 | 多角色并行:需求→设计→代码→质检,或内容生产全链路 | 任务拆解、多专家并行、端到端交付 |
| 外部信息调研与内容生成 | 需竞品分析、汇报材料的人 | 调研报告、PPT | 联网搜集、结构化写作、版式生成 |
| 业务数据洞察 | 运营/客成/管理 | 情感归类、问题提炼、策略建议 | 表格/日志理解、规律总结、方案生成 |

公开报道补充了几个产品设计上的关键取舍:

- **安全半自动,而非无限自主**:负责人公开表示,WorkBuddy 有意把自动化压在「半自动」区间——重复任务可自动跑,对外发布、高风险操作需人工确认;与追求高度自主的 OpenClaw 路线刻意错位。
- **沙箱与授权目录**:任务规划与文件操作强调本地优先,Agent 权限限制在用户授权的工作目录;避开「本地环境与远端透传直连」一类易引发数据泄露担忧的架构。
- **生态扩展**:支持 MCP、自定义 Skills,并宣称与 OpenClaw **技能生态兼容**(团队强调产品为自研 Agent 框架,并非套用 OpenClaw 源码)。
- **企业向延伸**:2026 年 6 月前后有企业版、微信支付 AI 专属卡接入等报道——把「能干活」继续接到支付与组织管控上(具体企业条款以官方当时页面为准)。

主流程(办公任务):用户下达意图 → 工作台规划并调度专家/技能 → 在授权目录与沙箱内读写文件、检索、生成交付物 → 高风险步骤弹出确认 → 输出报告/PPT/代码等可验收结果。人类角色是「指挥 + 关键节点放行」,而不是逐步手把手点菜单。

### Marvis:系统级 OS Agent——「把电脑变成可对话对象」

据官网 [marvis.qq.com](https://marvis.qq.com/) 与 2026 年 5 月一线报道,Marvis 由**应用宝团队**打造,定位明确写在简介里:**操作系统层级的个人 AI 助手**——自然语言操控电脑,支持多 Agent 协作、移动端远控 PC、智能文件处理、定时任务等。

能力与交互要点:

| 能力 | 说明 | AI / 系统介入点 |
|------|------|-----------------|
| 主从 Agent 协作 | 公开描述为约「1 主 + 5 副」:File / Computer / App / Browser / Search | 主 Agent 理解与调度,专项 Agent 执行 |
| 效率模式 / 隐私(本地)模式 | 效率:端云协同;隐私/本地:端侧模型,文件 0 上传,可断网 | 模式切换本身是产品核心开关 |
| 跨端远控 | 手机连接电脑,查看执行画面并可接管 | 远程画面 + 任务会话连续性 |
| 文件与系统 | AI 图库/文档库、内容搜索、一句话改系统设置 | 本地多模态理解 + OS 权限 |
| 安全兜底 | L2 级:删文件、改系统核心配置等须出计划并 Hard Confirm;支付等更高敏操作须用户本人完成;主动不碰微信/支付宝等资金隐私应用(报道口径) | 权限分级 + 强制确认 |

主流程(系统任务):用户一句话目标 → 主 Agent 拆步骤并调度专项 Agent → 读写本地文件/开应用/改设置/浏览检索 → 触及敏感操作则停下来给计划确认 → 用户可在手机端旁观或接管。与 WorkBuddy 相比,Marvis 更深度依赖**系统权限**(文件读写、系统设置、应用操控),因此「能不能干」和「敢不敢让你干」是同一设计问题。

### 对照:办公工作台 vs 系统级 OS Agent

| 对照轴 | WorkBuddy | Marvis |
|--------|-----------|--------|
| 默认战场 | 办公产出物(报告、PPT、数据洞察、开发交付) | 设备与文件生命周期(整理、设置、远控、跨 App) |
| 权限模型 | 授权工作目录 + 沙箱;偏「半自动」 | OS/应用级权限;L2 Hard Confirm + 支付红线 |
| 隐私卖点 | 本地优先、企业审计/受控技能包 | **隐私模式纯本地推理**作为一等公民开关 |
| 分发基因 | 腾讯云/CodeBuddy 开发者与效率产品线 | 应用宝「自下而上」:文件解析等底层工具 → Agent 框架 |
| 模型叙事 | 多专家、多模型协同(与混元等腾讯云能力同源报道较多) | 云端效率模式可用混元/DeepSeek 等;本地隐私模式报道多用端侧 Qwen 等(以当时产品设置为准) |
| 商业化信号 | 企业版、支付闭环、场景包;偏 B 与生产力变现 | 上线初期免邀请码 + 每日高额免费 Token;团队称长期完全免费不现实,或配额 + 自带 API Key |

一句话总结差异:**WorkBuddy 卖的是「办完一件办公事」;Marvis 卖的是「管住一台电脑」**。前者用场景包降低非技术用户的启动成本,后者用 OS 中间层换取更广的动作空间,也换来更重的安全与隐私设计负担。

## 三、技术方案推测

> 以下基于官网描述与公开报道的**推测**,腾讯未完整公开两套产品的内部架构,请勿当作确定性技术结论。

- **WorkBuddy(推测)**:复用 CodeBuddy 的 Agent 基建(规划、工具调用、技能/MCP),在桌面侧以沙箱隔离执行环境运行;多「专家」更可能是**角色化系统提示 + 工具集分工 + 并行子 Agent**,而非真的 100 个独立微调模型常驻。与 OpenClaw 的「技能兼容」更像协议/包格式层兼容,而非同一运行时。
- **Marvis(推测)**:典型「编排器 + 专项工具 Agent」结构;效率模式走端云协同(本地索引/预处理 + 云端复杂规划),隐私模式把推理压到端侧 NPU/CPU。跨端远控需要稳定的任务状态同步与画面流,**推测**存在独立的设备连接与会话层,而不仅是聊天记录同步。
- **共同的产品级技术命题(推测)**:两者都要解决 Agent 产品的 Token 成本远高于聊天助手——公开报道中 Marvis 团队已明确提到这一点;因此免费配额、自带 Key、企业席位,都会成为后续必答题,而不是上线彩蛋。

## 四、商业模式

截至 2026 年 7 月,两边都还处在「先抢心智与日活、再收紧计费」的阶段,公开标准价目表不如海外 Copilot/Claude 清晰,宜分信号看:

**WorkBuddy**

- **个人/小微**:免部署下载即用,靠场景包拉新;具体免费额度与付费墙以官网当时为准。
- **企业版**:报道指向组织管控、审计、受控技能、与腾讯云账号体系打通——更接近「卖安全可控的办公 Agent 能力」,而非单纯卖聊天次数。
- **生态位**:挂在 CodeBuddy 家族下,便于跟研发工作台、云资源、支付能力交叉销售。

**Marvis**

- **获客**:免邀请码、三端同步、每日高额免费 Token(报道口径,具体数字以官方活动为准)——用「系统级助手」心智换装机与权限授权。
- **长期**:团队公开表示 Agent Token 消耗高、完全免费不现实,**可能**走向基础配额 + 用户自带 API Key;与硬件厂商(报道提及英特尔端侧优化、微软 WinML 等)的合作更像分发/性能联盟,而非已成型的分成模型。

对 PM 的含义:WorkBuddy 的变现叙事更接近 **B 端效率软件**(场景价值 → 席位/企业版);Marvis 更接近 **平台级入口**(先占 OS 权限与跨端关系,商业化后置)。两条线同时推,也会带来内部定位摩擦——用户心智上「腾讯到底要我装哪个 Agent」需要持续用场景边界说清楚。

## 五、PM 视角的启示

1. **同一公司可以故意做两条 Agent 产品线,前提是权限边界与交付物定义清楚。** WorkBuddy 用「授权目录 + 半自动确认」换企业可接受的安全叙事;Marvis 用「OS 权限 + Hard Confirm + 支付红线」换系统级能力。模糊成「全能助手」反而两边都弱。
2. **大众化 Agent 的第一道门槛往往不是模型智商,而是部署与恐惧。** OpenClaw 教育了市场「AI 能操控电脑」,也教育了市场「乱装很危险」;WorkBuddy 的免部署与沙箱,本质上是在卖恐惧的对冲方案。
3. **隐私模式做成一等公民开关,是 OS Agent 的差异化筹码。** Marvis 把「文件 0 上传 / 可断网」做成效率模式的并列选项,比事后写隐私政策更有产品辨识度——尤其在国内对本地 Agent 数据外泄敏感的舆论环境下。
4. **规模数字要降级使用。** 渗透率、月访问量、留存等若只来自单一调研或转载,适合写「据某某报告/公司口径」,不适合写成行业共识;案例写作更应抓住可复核的产品机制(确认流、模式切换、场景包)。
