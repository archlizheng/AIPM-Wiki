# 大模型是怎么"想"的:预测下一个 token 的直观解释

## 一句话说清

大模型没有"理解"世界的方式和人类一样。它本质上是一个巨大的"接龙"系统:给定前面的文字,它反复做一件事——**预测下一个最可能出现的词(token)是什么**。对话、写代码、做数学题,表面上千变万化,底层都是这同一个动作在重复。

这句话听起来简单到有点反直觉:一个只会"猜下一个字"的系统,怎么能写诗、写代码、甚至通过律师资格考试?这正是本文要讲清楚的事——不是讲数学公式,而是讲这套机制如何在规模够大之后,"涌现"出看起来像智能的行为。

## Token:模型眼中的世界

人类读文字是一个字一个字、一个词一个词地读,模型也类似,只不过它的最小单位不是"字"而是 **token**。

- 一个 token 可能是一个完整的英文单词(`the`),也可能是半个词(`ing`、`un`)
- 中文里,一个 token 大致对应 0.5-1 个汉字,具体切分方式取决于模型的分词器(tokenizer)
- 图片、音频在多模态模型里也会被切成"token"式的单元,道理是相通的

模型不直接"看"文字,而是先把文字切成 token 序列,再把每个 token 转换成一串数字(向量)。之后所有的计算,都是在这些数字上进行的矩阵运算。

**PM 视角的意义**:API 按 token 计费、上下文窗口按 token 计算,理解 token 是理解成本和产品限制的第一步。

## 下一词预测:唯一的训练目标

大模型的预训练(Pre-training)阶段,目标出奇地朴素:**给一段文字的前半部分,预测下一个 token 是什么**。

打个比方:如果你从小到大读过互联网上几乎所有的书、新闻、代码、论坛帖子,做过一件事——每读一句话就停下来猜下一个词,猜错了就记住教训——你也会变得非常擅长"接话"。这正是大模型训练做的事,只是量级是数万亿 token,重复猜测数以万亿次,并通过反向传播不断修正参数,让"猜对"的概率越来越高。

这个过程完全不涉及"对错"的价值判断,模型学到的是**语言中的统计规律**:什么样的词后面倾向于跟什么样的词、什么样的句式对应什么样的上下文。这也是为什么幻觉问题在结构上无法根除的原因之一(详见[幻觉问题一文](hallucination.md))——模型的训练目标从来不是"说真话",而是"接得像"。

## 为什么"接话"能接出智能?

这是最反直觉的地方:一个只被训练去猜下一个词的系统,为什么能做推理、写代码、甚至规划?

**类比**:要把"下一个词"猜对,很多时候你必须先理解上下文的深层含义。比如续写"小明把伞借给了小红,因为下雨的时候小红没带伞,所以下雨天小明总是____",要猜出"淋湿"或"没有伞"这类词,模型必须在某种程度上"理解"因果关系、指代关系。当训练数据的规模和模型参数量都跨过某个门槛后,这种理解会从"记住表面模式"跃升为具备一定的抽象、组合和推理能力——业界把这种随规模跳跃式出现的能力叫做**"涌现"(Emergence)**。

Anthropic 的可解释性团队通过追踪模型内部的计算过程发现,大模型远不止"逐词接龙"这么简单。在研究 Claude 写押韵诗的例子中,研究者发现模型会先在内部"想好"要押的韵脚词,再倒推着组织前面的句子——这是一种真正意义上的"提前规划",而不是走一步看一步。同样,做心算时,模型会并行跑多条计算路径(比如一条估算大致范围,另一条精确计算末位数字),再综合得出答案。这些发现说明:"预测下一个词"是训练目标和输出方式,但模型内部形成的计算过程,已经不是简单的查表或者复读。

当然,这项研究也发现了值得警惕的一面:当计算太难时,模型有时会"编"一个看起来合理的答案而不是真正算出来;如果提前被提示了"标准答案",模型甚至会反向拼凑出看似合理的推导步骤——这与幻觉、"看人下菜"式的谄媚行为是同一类机制的不同表现。

## 温度与随机性:为什么每次回答不完全一样

模型每一步并不是"选出唯一确定的下一个词",而是先算出一个**概率分布**(比如"的"35%、"了"20%、"啊"5%……),再从中**采样**一个词作为输出。

**Temperature(温度)** 这个参数控制的就是这个分布的"平坦程度":

| 温度 | 效果 | 适合场景 |
|------|------|----------|
| 低(接近 0) | 分布更陡峭,几乎只选概率最高的词,输出稳定、保守 | 客服问答、代码生成、结构化输出 |
| 高(接近 1 或更高) | 分布更平坦,低概率词也有机会被选中,输出更有创意、更多样 | 创意写作、头脑风暴、生成多样化测试样本 |

这也是为什么同样的问题问模型两次,答案可能不完全一样——它本质上是一次带权重的随机抽样,而不是查表返回固定结果。关于这个话题更详细的参数对比和产品设计取舍,可参考面试题[《为什么大模型的输出每次都不一样?》](../../04-interview/basics/llm-output-randomness.md)。

## 预训练 → 后训练:从"接话高手"到"听话的助手"

只做完预训练的模型(称为 Base Model)其实并不好用——它只会"接龙",你问它"如何提高工作效率",它可能会把这句话当成一篇待续写的博客文章标题,继续写下去,而不是老老实实回答你。

要变成 ChatGPT、Claude 这样"听得懂指令、愿意好好回答"的助手,还需要**后训练(Post-training)**,通常包括:

1. **监督微调(SFT,Supervised Fine-Tuning)**:用大量"问题-高质量回答"的示例,教模型什么是一次"像样的回答"
2. **基于人类反馈的强化学习(RLHF)**:让人类(或者训练出的"打分模型")对模型的多个候选回答排序,再用强化学习让模型的输出向"人类更喜欢"的方向调整
3. **性格/价值观训练**:例如 Anthropic 在 Claude 3 起引入的"character training",专门训练模型的表达风格,让它显得诚实、不谄媚、乐于表达合理的不确定性,而不只是"什么都答对"

预训练决定了模型"知道什么、有多聪明",后训练决定了模型"愿意怎么回答、说话的样子"。两者合起来,才是我们日常使用的 ChatGPT、Claude、Gemini 这样的产品。理解这个大图景,能帮助 AI PM 想清楚:同样一个底层能力,可以通过不同的后训练策略,包装成完全不同性格和风险偏好的产品。

## 给 AI PM 的启示

- **"聪明"和"正确"是两件事**:模型的核心目标是"接得像",不是"说得对"。产品设计必须为这个 gap 做兜底(参考[幻觉问题](hallucination.md))
- **随机性是特性不是 bug**:该稳的场景调低温度,该有创意的场景调高温度,这是 PM 可以直接参与的产品决策
- **模型内部有"计算过程",不是纯粹的查表复读**:这解释了为什么它能做一定程度的推理,也解释了为什么它会在推理链里"造假"——理解这一点,对设计"展示推理过程"类产品功能(如思维链展示)非常关键
