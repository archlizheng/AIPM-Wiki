# 幻觉问题:成因与产品层面的缓解手段

## 一句话说清

幻觉(Hallucination)指大模型生成看起来流畅、自信,实则与事实不符或凭空捏造的内容。它不是模型"偶尔犯的小错误",而是这套技术路线在结构上很难彻底避免的特性。作为 AI PM,理解幻觉"为什么会发生",比背诵"怎么解决"更重要——因为只有理解成因,才能判断在自己的产品场景里,该往哪一层去做缓解。

## 幻觉的技术成因:为什么模型会"自信地编"

### 根源一:训练目标从来不是"说真话"

如[《大模型是怎么"想"的》](how-llm-works.md)一文所讲,大模型的核心训练目标是"预测下一个最可能的 token",不是"验证这句话是否为真"。当模型对某个问题缺乏足够信息时,它依然会继续"接话"——因为"拒绝回答"从来不是它被训练要去做的默认动作。这就好比一个背了很多知识但没有"我不知道"这个选项的学生,考试时哪怕完全没把握,也会习惯性地填一个看起来合理的答案上去。

### 根源二:评测和打分机制在"鼓励"模型瞎猜

OpenAI 在 2025 年发布的研究《Why Language Models Hallucinate》给出了一个关键洞察:幻觉之所以持续存在,很大程度上是因为**主流评测基准的打分方式**本身就在奖励"自信地猜",而不是奖励"诚实地说不知道"。

这篇研究把幻觉类比成统计学习中的**二分类错误**:如果"正确陈述"和"看似合理但错误的陈述"在统计上很难被区分开,那么生成模型犯这类错误就是概率必然,而不是偶然的工程 bug。更直白地说:模型是在被训练成一个"擅长应试的学生"——大多数评测只按"答对了多少题"打分,回答"不知道"和答错了一样是 0 分,那么理性策略当然是"能蒙就蒙",而不是承认不确定。这篇研究提出的解法也很直接:不是再造一套新的"幻觉专项评测",而是**改造现有主流评测的打分规则**,让"诚实表达不确定"不再被系统性地惩罚,从而扭转整个行业的优化方向。

### 根源三:模型内部的"默认拒答电路"会被错误地压制或激活

Anthropic 的可解释性研究团队通过追踪 Claude 内部的计算过程发现一个有意思的机制:模型内部存在一个"默认开启"的电路,倾向于让模型表达"我信息不足,无法回答"。但当模型识别到某个实体或概念"看起来眼熟"(比如一个熟悉的人名、书名),这种"眼熟感"对应的特征会去抑制默认的拒答倾向——如果这种识别是错的(比如认错了实体,或对该实体的了解其实很浅),模型就会在没有真正把握的情况下继续往下编,产生幻觉。研究还发现,当计算或推理确实太难时,模型有时会"编"一个看似合理的答案而不是老实展示"我算不出来";如果提前被暗示了目标答案,模型甚至会反向拼凑出一套"推导过程"来凑答案——这类"言之凿凿但站不住脚"的表现,和普通意义上的幻觉是同一类问题的不同侧面。

**一句话总结成因**:幻觉不是模型"坏了",而是"预测下一个词"的训练目标、"奖励自信而非诚实"的评测方式、以及模型内部对"熟悉度"的误判,三者叠加的结果。

## 哪些场景容易高发

| 场景类型 | 为什么高发 | 典型例子 |
|----------|-----------|----------|
| 长尾 / 冷门知识 | 训练数据中该内容出现次数少,模型没有稳固的"记忆",但依然会强行补全 | 询问某本小众书籍的具体章节内容、某个小众历史事件的细节 |
| 需要精确数字/引用的任务 | 模型擅长"语义上合理",但不擅长精确复现具体数字、页码、法条编号 | 编造论文引用、编造法条序号、编造统计数字 |
| 超出训练数据时效范围的问题 | 模型的知识有截止日期,遇到之后发生的事,它可能"接话"编一个看似合理的答案而非说"我不知道" | 询问模型知识截止日期之后发生的新闻 |
| 多步推理链较长的任务 | 中间某一步出错后,后续步骤会在错误基础上继续"自圆其说" | 复杂数学题、多跳逻辑推理 |
| 被诱导性提问 / 暗示答案 | 模型会顺着提示"回填"一套看似合理的推导,而非独立验证 | "是不是因为 A 所以 B?"这类带倾向性的提问 |

## 产品层面的分层缓解手段

幻觉无法被"消灭",但可以在多个层面做工程化控制,把风险压到业务可接受的水位。下表从模型层到用户教育层,由内到外梳理:

| 层级 | 手段 | 说明 |
|------|------|------|
| **模型 / Prompt 层** | 明确允许拒答、要求高置信度才回答 | 在系统提示词中告诉模型"不确定就说不知道",比默认放任模型"必须给个答案"能显著降低强行编造的概率(参考 Anthropic 官方的 Reduce Hallucinations 指南) |
| **模型 / Prompt 层** | 降低 Temperature | 减少输出的随机发散程度,对事实性问答场景有帮助,但不能根治(参考[《为什么大模型的输出每次都不一样?》](../../04-interview/basics/llm-output-randomness.md)) |
| **模型 / Prompt 层** | 先取证再回答 | 要求模型先从材料中摘录相关原文,再基于摘录内容作答,而不是直接给结论 |
| **检索层** | RAG(检索增强生成) | 用外部真实资料约束生成内容,而不是让模型完全依赖内部记忆自由发挥(详见[《什么是 RAG》](what-is-rag.md)) |
| **检索层** | Rerank / 检索质量优化 | 光有 RAG 不够,检索回来的材料本身要相关、要新——检索不准,幻觉照样发生 |
| **验证层** | Best-of-N 交叉验证 | 让模型对同一问题生成多次,比较输出间是否一致,不一致往往是幻觉信号 |
| **呈现层** | 引用溯源(Citation) | 展示答案对应的原文出处,让用户可以点击核验,即使模型出错,用户也能快速发现 |
| **产品兜底层** | 拒答 / 降级策略 | 检索不到可靠材料时,宁可明确告知"没有找到相关信息",也不要让模型自由发挥 |
| **产品兜底层** | 人工复核 / 高风险场景阻断 | 医疗、金融、法律等高风险领域,关键结论走人工复核或强制提示"仅供参考,请核实" |
| **用户教育层** | 预期管理 | 明确告知用户"AI 回答可能出错,请对重要信息进行二次核实",避免用户对 AI 输出建立盲目信任 |

### 选型思路:不是所有场景都要"零幻觉"

- **高风险场景**(医疗诊断建议、金融投资建议、法律意见):优先"宁可不答也不乱答",拒答策略 + 强制引用溯源应该是标配
- **低风险场景**(创意写作、头脑风暴、营销文案):可以容忍一定的"编造",甚至这种发散本身是价值所在
- **中间地带**(客服问答、企业知识库问答):RAG + 引用溯源通常是性价比最高的组合拳,既约束了内容来源,又给了用户核验的手段

治理幻觉的本质,不是找一个"一招制敌"的技术方案,而是根据业务的风险容忍度,在模型层、检索层、呈现层、产品兜底层做组合式的工程投入。

## 给 AI PM 的启示

- 向团队和老板解释幻觉时,不要只说"模型有时候会编",要能讲清楚"为什么会编"——这决定了大家会不会认真投入资源做分层治理,而不是简单粗暴地"优化一下 Prompt"就了事
- 排查线上幻觉问题时,先拆分是"检索环节没找到对的材料"还是"生成环节没用好材料",这是两类完全不同的 badcase,对应不同的修复方向
- 引用溯源(Citation)的设计质量,直接决定了用户对幻觉的"容错体验"——即使模型偶尔出错,清晰的引用来源能让用户自己快速发现问题,而不是被误导
