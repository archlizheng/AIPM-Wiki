# AI 产品成本测算入门:token、并发与人力

> **信息状态**：动态快照｜**最后核验**：2026-09-14

> 以下价格为 2026-09-14 访问官方页面时看到的示例，价格、模型可用性和促销会变化；正式预算应保存访问日和对应页面快照。

做 AI 产品的 PM,绕不开一个问题:这个功能上线后,每个月要花多少钱?这笔账算不清楚,PRD 里的"预期效果"就是空中楼阁——功能越受欢迎,账单可能越吓人。本文教你从 token 计费的基本逻辑出发,搭一套自己能复用的估算方法。

## 一、token 计费怎么算

本文列举的大模型 API 按 **token** 计费,而不是按"字"或"次"计费。token 是模型处理文本的最小单位,一次调用的基础文本费用由输入、输出两部分构成:

```
单次调用成本 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
```

几个新手常踩的坑:

1. **输入和输出单价不同**。当前示例中 Claude Sonnet 5 为输入 $2、输出 $10/百万 token，GPT-5.6 Terra 为输入 $2、输出 $12/百万 token；应按实际模型和输出上限测算，不能把某一倍率当作行业规则。
2. **中文和英文的 token 换算不能套用通用比例**。不同模型、分词器、文本格式和标点都会改变结果；精确估算应使用对应厂商 tokenizer 或 API 实测，并在成本表中保存文本样本与模型版本。
3. **不同模型的分词器(tokenizer)不一样**。Anthropic 官方说明，Claude Opus 4.7 及之后模型、Fable 5、Mythos 5 和 Sonnet 5 使用新分词器，同样文本约多出 30% token；精确估算应使用对应厂商工具实测。
4. **系统 Prompt、历史对话、工具调用定义都算输入 token**。很多团队只算"用户这句话"的 token,却漏算了系统 Prompt 和多轮历史——这往往是实际账单超出预期的头号原因。

## 三、完整估算案例:DAU 10 万的问答助手功能

以下是与内部 IT 助手教学账本**独立的教学算例**：假设你负责一款内容类 App,准备上线一个"AI 问答助手"入口,预计 DAU(日活)10 万。它不代表任何真实产品现状、渗透率或预算，我们来完整算一遍月度模型成本。

### 第一步:列出假设

| 参数 | 假设值 | 依据/说明 |
|------|--------|-----------|
| DAU | 100,000 | 本节独立教学题设，不代表真实产品现状 |
| 功能渗透率 | 30% | 本节教学假设，不代表同类产品基线 |
| 日活跃使用用户 | 30,000 | DAU × 渗透率（教学演算） |
| 人均日调用次数 | 5 次 | 本节教学假设，真实值需由日志或试点测量 |
| 每次输入 token | 600 | 系统 Prompt(~150)+ 检索片段/历史上下文(~300)+ 用户当轮输入(~150) |
| 每次输出 token | 250 | 中等长度回答 |
| 选用模型 | Claude Sonnet 5 | 仅作成本算例；正式选型仍需效果、延迟、合规评测 |

### 第二步:计算

```
日调用次数 = 100,000 × 30% × 5 = 150,000 次/天
月调用次数 = 150,000 × 30 天 = 4,500,000 次/月

月输入 token = 4,500,000 × 600 = 2,700,000,000(27 亿)tokens
月输出 token = 4,500,000 × 250 = 1,125,000,000(11.25 亿)tokens

月输入成本 = 2,700 × $2.00  = $5,400
月输出成本 = 1,125 × $10.00 = $11,250
月模型成本合计 ≈ $16,650

按 1 美元 ≈ 7.2 人民币折算(汇率仅作示意,请以当期汇率为准):
月成本 ≈ ¥119,880，约 ¥12 万
```

### 第三步:敏感性提示

这笔账最容易失真的三个变量,上线前要单独测算区间而不是只给一个数字:

| 变量变化 | 对月成本的影响 |
|----------|----------------|
| 渗透率 30% → 60%(功能爆火) | 成本 ×2 |
| 人均调用 5 次 → 10 次(用户养成多轮追问习惯) | 成本 ×2 |
| 换用 Opus 5（仅按 Token 价格估算） | 成本约 ×2.5 |
| 引入 RAG,输入 token 从 600 涨到 1500 | 成本明显上涨,输入部分 ×2.5 |

给管理层汇报时,应同时给出教学基准和敏感性参数，不能把本节约 ¥12 万或某个固定区间当作真实产品预算；渗透率、调用次数、上下文长度和模型价任一变化都应触发重算。关于面试中常考的"如何拆解假设""如何做敏感性分析",可参考 [估算日活 100 万的 AI 对话产品每月模型调用成本](../../04-interview/case-analysis/estimate-daily-active-chat-cost.md)。

## 四、别忘了:API 调用费不是全部成本

很多 PM 做 ROI 测算时只看模型 API 账单,容易大幅低估真实成本。一个 AI 功能从预研到稳定运营,完整的成本构成大致如下:

| 成本项 | 说明 | 估算依据 |
|--------|------|------------------------------|
| 模型 API 调用 | 上文计算的部分 | 基准 100% |
| 数据标注 | 训练/评估数据的人工标注,尤其是效果评估集 | 标注单价 × 样本量；区分首次建集与持续回流 |
| 效果评估与测试 | Badcase 复核、评测集维护、人工抽检 | 复核样本数 × 单条工时 × 人工费率 |
| 向量数据库/检索基础设施 | 若功能涉及 RAG | 按供应商存储、查询和计算价目测算 |
| 人力(算法+工程+产品) | Prompt 迭代、评估体系搭建、上线运维 | 按角色投入工时 × 内部费率列账，勿漏初始建设成本 |
| GPU 资源(若自建部署) | 仅在决定私有化部署时产生 | 需要达到一定调用规模才划算,见[《模型选型决策框架》](model-selection-framework.md) |
| 安全与合规审查 | 内容安全、数据合规评估 | 视行业和监管要求,可能是持续性投入 |

API 费之外还要列出标注、评估、基础设施、安全合规和人力；它们的比例取决于任务、规模和组织，本文不提供统一倍数或“同一量级”的行业经验法则。

## 五、给 PM 的估算模板

写 PRD 或做成本评审时,可以直接套用下面的模板,把假设和公式都摆在明处,方便被追问和复核:

```
【产品形态】:一句话描述场景(单轮问答 / 多轮对话 / Agent 多步调用 / 批量处理)

【核心参数假设】
- DAU / 目标用户规模:
- 功能渗透率:
- 人均日调用次数:
- 每次输入 token(拆分:系统 Prompt + 上下文/检索片段 + 用户输入):
- 每次输出 token:
- 拟选用模型及单价:

【计算公式】
月调用次数 = DAU × 渗透率 × 人均日调用次数 × 30
月输入成本 = 月调用次数 × 每次输入 token ÷ 1,000,000 × 输入单价
月输出成本 = 月调用次数 × 每次输出 token ÷ 1,000,000 × 输出单价
月模型成本 = 月输入成本 + 月输出成本

【非 API 成本补充】
- 标注/评估人力:
- 基础设施(向量库等):
- 是否需要预留 GPU/自建评估:

【敏感性说明】
列出 2-3 个最可能变化的参数,给出成本区间而非单一数字
```

这套模板配合上文的价格表,基本能覆盖大多数"某功能上线后成本多少"的评审场景。下一步该关心的是"选哪个模型才是效果、成本、延迟、合规的最优解",请看[《模型选型决策框架》](model-selection-framework.md);如果账算出来觉得太贵,直接跳到[《降本手段盘点》](cost-optimization.md)。算清功能账单之后,还要把同一套单位经济学接到岗责与定价评审上——见下一节。

## 六、隐性成本与「高薪错觉」

> **补充于 2026-08**：选题启发自磊叔《关于 AI 产品经理的 100 个问题》Q6。正文为原创框架;**不**采用该文中的薪资区间、涨薪比例或「Token 占营收 X%」等未外证数字当行业标准。

看招聘价码,容易把 AI PM 想成「金饭碗」。更值得算清的是另一件事:**这个岗位要为怎样的边际成本结构负责**——个人包看起来高,并不等于业务的单位经济学轻松。

### 和传统软件差在哪

| | 传统软件 / 经典 SaaS | 大模型驱动的 AI 功能 |
|--|---------------------|---------------------|
| 多服务一个用户 | 边际成本主要是固定云资源分摊 | 几乎每次调用都产生 Token / 推理费用 |
| 产品「成功」意味着 | 规模摊薄固定成本 | 活跃、多轮追问、Agent 多步上升时,**账单与成功绑在一起** |
| 岗责常被误读成 | 交付功能与增长 | 还要持续守住单位任务成本,并把成本底线嵌进定价 |

第四节列的是**功能级**非 API 项(标注、评估、向量库、人力、合规)。这里的「隐性」多一层含义:评审若只报模型费、不报暗成本、也不问定价能否托住,岗位溢价对应的判断责任其实没有兑现——这就是「高薪错觉」在成本语境下的所指,而不是去争论某城某档薪资该不该拿。

### 怎么算(框架三步,不抄百分比红线)

1. **可见账单**:用上一节模板估月度模型成本与敏感性区间。
2. **摊到每次有效调用**:把延迟损耗、人工兜底、迭代/评估摊销、基础设施、合规等写进单位成本——见[《降本手段盘点》·暗成本](cost-optimization.md#八暗成本token-账单之外的单位经济学)。品类上「模型费占营收多少算健康」只能用**自有财务目标**校准,不要背外部分位数,见同文[品类成本框架](cost-optimization.md#九品类成本框架别拿单一占营收-x当行业标准)。
3. **对照定价底线**:贡献毛利能否覆盖变动推理成本与必要兜底;订阅还要看 P90 用量而不是均值——见[《AI 产品定价与商业化》](ai-pricing-and-monetization.md)第五节「成本底线」。

再补一条常见误判:**模型单价下降 ≠ 总成本下降**。效率变好、单次变便宜后,更长上下文、更多轮、更重 Agent 形态常会把总消耗顶回去(Jevons 机制),说明见[《降本手段盘点》·Jevons 悖论](cost-optimization.md#十jevons-悖论单价降了总账单为什么可能涨)。

**落地一句话**:谈岗责或 ROI 时,把「能否独立拆清 Token + 暗成本 + 定价能否托住」当作能力锚点;具体降本组合与反模式继续读降本文,商业契约怎么选读定价文。
