# 为主流电商平台设计智能客服问答机器人(含兜底机制)

**难度**:⭐⭐⭐ 进阶
**出现频率**:高(牛客 JD 押题帖、蚂蚁 AI 客服面经)

## 考察点

- 能否把「咨询问答」拆成可落地的意图、知识、动作三层,而不是堆一个聊天框
- 技术选型是否匹配电商场景(订单/物流/售后强结构化)
- 兜底机制是否分层设计,而非一句「转人工」

## 参考答案

**一句话**:电商客服机器人的核心是「高频标准问题 AI 闭环 + 高风险/低置信度快速转人」,知识靠 RAG,行为靠 Prompt/轻量微调,兜底按置信度与业务风险分级。

### 1. 澄清与界定

先对齐范围:面向**已下单用户**的售后/物流/退换货咨询(占工单 60%+),暂不覆盖售前比价。成功指标分三层:

| 层级 | 指标 | 目标方向 |
|------|------|----------|
| 效果 | 一次解决率(无需转人工) | ≥75% |
| 体验 | 平均响应时延 | P95 <3s |
| 安全 | 错误承诺率(如错赔/错退) | 趋近 0 |

### 2. 方案设计

核心流程:**意图识别 → 槽位补全(订单号/商品) → 查业务系统 + 知识库 → 生成回复 → 置信度判断 → 闭环或升级**。

高频场景模板化:物流轨迹、退款进度、发票开具——走**结构化 API + 固定话术**,减少幻觉。复杂纠纷(质量问题、价保争议)默认低置信度,缩短路径转人工。

### 3. 技术方案

| 模块 | 选型 | 理由 |
|------|------|------|
| 知识问答(政策/FAQ) | RAG + 引用溯源 | 规则频繁变更,需可审计 |
| 意图与槽位 | Prompt + 小模型分类器 | 电商意图有限,分类比端到端生成稳 |
| 语气与合规 | 轻量 SFT 或强 Prompt | 统一品牌口吻,禁止过度承诺 |
| 多步操作(改地址) | Agent 工作流 | 需调订单 API,非纯聊天 |

参考 [RAG 和微调选型](../basics/rag-vs-finetuning.md):知识更新走 RAG,说话风格走 Prompt/SFT,不互斥。

### 4. 风险与兜底(分层)

1. **模型层**:检索不到或生成置信度 <阈值 → 不编造,回复「暂未查到,为您转专员」
2. **业务层**:涉及赔付/退货审核 → 无论置信度多高都转人工或走审批流
3. **体验层**:用户连续 2 次点「没解决」→ 自动升舱 + 带入上下文
4. **合规层**:敏感词、威胁投诉 → 优先人工,AI 不做最终裁决

### 5. 衡量与迭代

上线后按意图拆解决率漏斗:哪类意图转人工最多 → 补知识库或加 API。bad case 回流标注,每周复盘 Top 20 错题。延迟与准确率冲突时,标准问答走缓存/小模型,复杂问才上大模型(见 JD 押题「准确性 vs 延迟」考点)。

## 追问延伸

- **追问 1**:"用户问『我的包裹怎么还没到』,你怎么答?"
  → 先识别需订单号,调物流 API 返回节点;无单号则引导绑定订单,不凭空编轨迹。
- **追问 2**:"RAG 检索到了过时退货政策怎么办?"
  → 知识库版本管理 + 生效日期元数据;生成时强制引用条款编号,便于客服复核。
- **追问 3**:"解决率和满意度冲突怎么办?"
  → 解决率看是否闭环,满意度看 NPS/差评;对「强转人工但用户满意」的场景单独建指标,避免 AI 硬撑。
