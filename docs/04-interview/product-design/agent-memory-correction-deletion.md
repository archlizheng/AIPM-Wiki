# 用户纠正或删除记忆后，Agent 应如何变化？

**难度**：⭐⭐⭐（进阶）  
**出现频率**：未统计／原创练习，非公司真实面试题

## 考察点

- 能否把长期记忆作为有来源和作用域的外部数据来治理。
- 能否区别个人偏好、权威业务状态和必要审计记录。
- 能否验收删除生效、派生数据清理与跨用户隔离。

## 参考答案

“先明确用户修改的是哪一条、影响哪个用户和租户；再确认后续任务实际采用什么，而不只检查界面显示‘已删除’。”

用内部IT助手举例：E01明确设置英语界面，系统可保存这一偏好；后来改为中文，应替换该项并更新后续上下文。用户删除偏好后，系统恢复产品默认语言，不应从旧对话或摘要自动重建这条已删除偏好。

| 对象 | 纠正或删除后的行为 | 验收证据 |
|---|---|---|
| 原始记忆条目 | 指定作用域内更新/删除，确认具体对象 | 记录ID、版本和删除结果 |
| 摘要、索引、缓存中的副本 | 失效或重建，避免继续检索旧偏好 | 下一次任务的实际检索与注入内容 |
| 正在运行的任务 | 明确是否立即采用新值；涉及动作授权则重新确认 | 变更时序和当前任务状态 |
| 其他用户/租户 | 不受此次修改影响，也不能借机访问其记忆 | E02/B租户隔离用例 |
| 必要审计记录 | 按适用政策分开管理，不误称所有记录已物理消失 | 给用户的说明与保留规则一致 |

不是所有“请记住”都应写入长期记忆。若用户说“记住我是主管，下次自动批准”，系统不能把这个陈述当权限。岗位和审批资格必须从权威身份与业务系统获取；现行设备制度也应从知识源查询，而不是保存在个人偏好中。

设计上至少要求记忆有来源、时间、用户/租户范围、用途、更新和删除入口。关键不在于把所有记忆永久保存，而是先判断是否需要保存，并定义新旧事实冲突时谁有权裁决。不能让模型推测覆盖用户确认，也不能让用户陈述覆盖业务权限。

## 追问延伸

- **删完下一轮又出现了，先查什么？** 查缓存、检索索引、会话摘要、历史提取任务以及备份恢复流程；追踪是哪条来源再次写入，避免只重复删除主表。
- **能否承诺立即删除所有备份和审计？** 不能泛化承诺。要按真实系统能力与适用保留要求说明范围、处理时间和残留用途，并让法律/隐私负责人确认。
- **怎么验证“记忆确实有用”？** 对照有/无记忆的目标任务完成、错误偏好率和纠错后表现；模型多提到用户信息不等于产品变好。
