# 为电商 App 设计一个 AI 导购

**难度**:⭐⭐⭐ 进阶
**出现频率**:高(电商 AI 场景 JD 押题、行业通用框架题)

## 考察点

- 能否区分「搜索推荐」与「对话导购」的产品价值
- AI 是否真正缩短决策链,而非增加干扰
- 商业化(转化、客单)与技术成本的平衡

## 参考答案

**一句话**:AI 导购不是聊天卖货,而是**在决策关键时刻(比选、凑单、犹豫)给可执行的推荐与理由**,最终仍回到商详/下单,转化可衡量。

### 1. 澄清与界定

**用户**:有购买意图但**选择困难**的用户(3C、美妆、母婴尤甚),非纯闲逛流量。

**问题**:参数难懂、评价水军多、促销规则复杂,导致加购高、下单低。

**指标**:导购会话 → 商详点击率 → 下单转化率 → 客单价;辅以用户满意度(推荐是否「懂我」)。

**非目标**:不做无边界闲聊;不替代搜索框处理明确品牌型号查询。

### 2. 方案设计

**入口**:商详页「帮我选」、购物车「凑单建议」、列表页悬浮「对比这三款」。

**核心流程**:

1. **澄清需求**(预算、用途、禁忌)——少问精准,多问结构化选项
2. **检索 + 对比**——调商品库、评价摘要、参数表
3. **给 2–3 个选项 + 理由**——卡片化,一键加购
4. **跟进**——「要更轻便的吗」单轮追问,避免无尽对话

AI 角色:**决策压缩器**,不是推销员。

### 3. 技术方案

| 模块 | 方案 |
|------|------|
| 商品/评价知识 | RAG + 商品图谱(品类属性、互斥关系) |
| 个性化 | 用户行为序列 + Prompt,慎用过度个性化致隐私争议 |
| 促销规则 | 规则引擎算凑单,LLM 只解释「为什么这样凑」 |
| 对比表 | 模板化生成 + 引用评价片段,防幻觉 |

高并发场景可对热门 SKU **预生成对比摘要**缓存,平衡延迟与准确性(JD 押题考点)。详见 [RAG vs 微调](../basics/rag-vs-finetuning.md)。

### 4. 风险与兜底

- **幻觉**:价格、库存、功效宣称必须 API 实时校验;不确定则说「以商详为准」
- **误导消费**:不推荐超预算太多;敏感品类(药、婴)加合规话术与免责
- **体验**:可随时「关闭导购」回传统浏览;不遮挡核心购买按钮
- **冷启动**:新用户用热门场景模板(「送女友礼物 500 元」),逐步学习偏好

### 5. 衡量与迭代

A/B:导购组 vs 对照组的转化率与退款率(防「忽悠下单」)。按品类拆效果,美妆有效不代表 3C 有效。用户点「没用」的 query 回流,补知识库与对比维度。

## 追问延伸

- **追问 1**:"和推荐算法有什么区别?"
  → 推荐是被动排序;导购是主动澄清 + 可解释对话,服务长尾、复杂决策。
- **追问 2**:"商家会不会反感 AI 不推荐自家贵款?"
  → 声明中立策略;广告位与导购分离;长期信任 > 短期佣金。
- **追问 3**:"成本怎么控?"
  → 意图分流:型号查询走搜索,仅复杂比价走大模型;会话长度上限。
