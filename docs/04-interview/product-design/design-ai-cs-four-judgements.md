# 面试官让你「设计一个 AI 客服」，3 分钟内必须说清哪些判断点？

**难度**:⭐⭐ 常规
**出现频率**:高（开场压题 / 与长设计题搭配出现）

> **与长设计题分工**：本题是 **3 分钟判断框架**——先证明你会「想清楚再画方案」。完整流程、意图分层、技术选型与分层兜底细节，见 [为主流电商平台设计智能客服问答机器人](design-ecommerce-customer-service-bot.md)；解决率卡点与漏斗诊断见 [解决率停在 70% 上不去](ai-customer-service-resolution-rate.md)。
>
> **选题启发**：磊叔《关于 AI 产品经理的 100 个问题》Q5（仅选题结构，正文为原创）。

## 考察点

- 开场是否先做**判断与边界**，而不是立刻堆功能清单或「接个大模型聊天框」
- 四个判断点是否形成**可推进的决策顺序**（场景 → 效果 → 兜底 → 成本风险），而不是四个平行口号
- 能否在 3 分钟内留下「可追问的钩子」，方便面试官切入长设计 / 指标 / 合规

## 参考答案

**一句话**：3 分钟不讲完整架构，只讲清四件事——**服务谁、什么叫做好、做不好怎么接、值不值得做且不能翻车**。顺序固定，漏任何一点都像「还没想清楚就开工」。

### 开场 10 秒：先界定题型

「设计一个 AI 客服」题面过宽。先用一句话收窄假设，例如：「假设是电商售后里的物流与退换咨询，目标是提升一次解决率并可控地转人工。」收窄不是偷懒，是避免 3 分钟散成百科。若面试官要换场景（金融 / ToB SaaS），四个判断点结构不变，只换约束。

### 四个判断点（建议按此顺序说）

| 顺序 | 判断点 | 3 分钟里必须落地的一句话 | 常见踩坑 |
|------|--------|--------------------------|----------|
| **1** | **场景与边界** | 谁在什么渠道问什么；AI **独立闭环** vs **必须转人 / 拒做** 的清单 | 上来列「查物流、退款、投诉、售前」一锅端 |
| **2** | **效果与评测** | 「解决」怎么定义；上线看什么主指标 + 哪条红线指标 | 只喊准确率 / 解决率，不说口径与反指标 |
| **3** | **兜底与转人工** | 低置信 / 高风险 / 用户不满时怎么升舱；转人是否带上下文 | 一句「转人工」当万能结尾，无分层触发 |
| **4** | **成本与风险** | 单次会话成本与人效账；幻觉承诺、越权操作、合规的硬闸门 | 只谈体验不谈 Token/坐席 ROI，或只谈省人不论翻车 |

#### 1. 场景与边界：先画「能做 / 不做」

判断内容：用户身份（已登录买家 / 访客）、渠道（App 在线 / 工单 / 电话转写）、问题类型（状态查询 / 政策问答 / 需改订单的动作）。

产品结论要落到边界表，而不是功能 wishlist：

- **AI 闭环**：高频、可查证、可逆或低金额——如物流节点、发票进度、标准退货时效说明
- **AI 辅助人工**：需裁量或纠纷——如质量争议、价保谈判
- **禁止 AI 终裁**：资金赔付承诺、法律威胁、账号安全核身等——规则拦死，不靠模型「自觉」

边界说不清，后面的解决率与成本账都会失真。行业形态与「按结果付费」为什么能跑通，见案例 [智能客服拆解](../../03-case-studies/vertical/ai-customer-service.md)。

#### 2. 效果与评测：先锁口径，再谈数字

判断内容：什么叫「解决了」——用户点已解决？N 小时内未再进线？业务状态确已变更（退款到账）？

面试里给**分层指标**即可，不必背行业普适百分比：

| 层级 | 问什么 | 例子 |
|------|--------|------|
| 主效果 | AI 是否独立闭环 | 一次解决率（需声明排除本就不该 AI 处理的工单） |
| 体验 | 快不快、烦不烦 | 首响、平均轮次、CSAT |
| 红线 | 错了会伤信任/钱 | 错误承诺率、二次进线率、高风险误操作率 |

加分句：离线评测集（意图覆盖、口语、多轮、API 失败）与线上漏斗要对齐；「模型准确率 90%」≠「解决率 90%」。深入诊断链到 [解决率卡点题](ai-customer-service-resolution-rate.md)。

#### 3. 兜底与转人工：把「失败路径」当一等公民

判断内容：触发条件不是「模型心情不好」，而是可产品化的信号——检索空、置信度低、命中高风险意图、用户连续点「未解决」、工具调用失败。

3 分钟版分层（细节留给长设计题）：

1. **低风险不确定** → 缩小回答 / 追问槽位 / 给自助链接，不编造
2. **高风险或不可逆动作** → 无论置信度多高，确认或转人（对齐 [Agentic UX 与信任校准](../../02-pm-skills/prd-and-design/agentic-ux-and-trust-calibration.md) 的副作用分级）
3. **体验崩盘** → 快速升舱，**带会话摘要与已查订单**，人工不是从零开始

兜底话术与预期管理控件，见正课 [兜底、反馈与预期管理](../../02-pm-skills/prd-and-design/fallback-and-feedback-design.md)。

#### 4. 成本与风险：证明你算过账，也守过底线

判断内容分两块，各用一句话带过：

- **成本**：AI 客服的账通常是「Token / 调用 + 知识运营 + 人工兜底」vs「节省的坐席时长 / 夜间覆盖」。先做窄场景闭环，再扩覆盖——避免全量流量砸大模型。
- **风险**：对外承诺以业务系统与生效政策为准；退款/改址等写操作要鉴权与审计；生成式服务还要内容与日志合规意识（不在此背法规条文，但要点名「有红线闸门」）。

成熟产品把「知道何时不解决」与「解决率」同等重要——案例里 Fin / Sierra 的公开设计可作旁证，见 [智能客服拆解](../../03-case-studies/vertical/ai-customer-service.md)。

### 3 分钟收束句（可背）

「我先定场景与不做清单，再定解决口径与红线指标，然后设计分层转人工，最后用成本账和风险闸门决定自动化比例——细节方案可以按你关心的电商/金融场景再展开。」

此时面试官若说「展开讲」，无缝切到 [电商客服长设计题](design-ecommerce-customer-service-bot.md) 的五段结构。

## 追问延伸

- **追问 1**:"这四个点和通用 AI 产品设计框架有何不同？"
  → 骨架通用（澄清 → 方案 → 风险 → 指标），客服题把 **转人工** 与 **解决口径** 提到一等公民，因为商业价值几乎总换算成「少接多少通、错答代价多大」。
- **追问 2**:"如果面试官只要你立刻讲功能列表怎么办？"
  → 先用 20 秒抛边界与指标，再给 3 个高频闭环功能 + 1 条转人规则；功能是判断点的结果，不是替代品。
- **追问 3**:"ToB 客服和电商 C 端有何差别？"
  → 判断点不变；ToB 更强调租户知识隔离、权限与审计、按坐席/按结果的计价口径；C 端更强调峰时延与大促熔断。
