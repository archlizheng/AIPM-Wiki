## 各轮详情

### 面试题摘录

#### 09. 面向专业用户的 Agent 该如何设计 Benchmark？

原文观点包括：

- 专业 Agent 的 Benchmark 不应只测模型能力，还要测业务可用性和安全底线。
- 以法律尽调 Agent 为例，测试集应来自真实业务中的脏数据和失败案例，而不只是干净的公开题库。
- 可以加入长合同、补充协议、财务材料、冲突条款、隐藏责任和误导性描述，测试 Agent 是否能在长文本中发现风险。
- 专业场景的指标应允许非对称取舍：高风险召回率应优先于漂亮的精准率，漏掉致命问题的代价更高。
- 每个结论都应能溯源到原文页码和段落，引用幻觉应视为严重问题。
- 评测可以由专家先定义评分细则和样本，再结合领域裁判模型批量评测，同时保留专家抽检、红蓝对抗和随真实业务滚动更新的测试集。

**整理后的回答框架**：业务目标与风险 → 真实数据构造 → 指标设计 → 证据溯源 → 裁判机制 → 线上反馈闭环。

#### 10. 如果负责 Kimi 的下一增长曲线，会选哪个方向？

原文选择面向 Prosumer 的状态化工作空间，而不是继续竞争泛 C 端问答流量，主要理由包括：

- Kimi 的长文本能力可以带来初始关注，但纯 Chat 的迁移成本低，用户可以轻易切换到其他模型。
- 目标用户可以是律师、研究员、投资分析师、内容创作者和代码极客等高信息密度、重任务、愿意为效率付费的人群。
- 产品形态应从一次性对话变为持久项目空间，沉淀财报、合同、论文、批注和历史结论。
- Kimi 可以基于这些沉淀生成看板、数据库和分析草稿，并逐渐理解用户的关注维度、表达风格和资料结构。
- 长期壁垒不是某次回答更好，而是用户离开后需要重新培养一个懂自己的数字分身。

**整理后的回答框架**：现有优势 → 用户分层 → 产品形态变化 → 用户资产沉淀 → 使用惯性与商业化 → 竞争壁垒。

## 总结与建议

- 这篇面经适合用于准备 Agent 评测、专业场景产品设计和 AI 产品增长曲线题。
- 专业 Agent 的评测不能只看平均准确率，应同时考虑高风险召回、证据溯源、安全边界和真实业务数据。
- AI 产品增长题要避免只讲“增加用户”，还要分析用户资产、迁移成本、使用惯性和付费价值。
- 当前资料只包含两道题，不能据此还原 Kimi 的完整面试题库。
