## 各轮详情

### 一面

**问题清单**:

1. 第二段实习的 AI 产品需求是什么
2. RAG 原理是什么
3. 学校项目做的 BERT 调优是怎么做
4. BERT 和大模型有什么区别
5. 从输入输出上讲一下区别

**一面反问**:

- 业务线是什么（答复：消费者 BG，做交付）

**参考回答思路**:

- **AI 需求**: 用「用户—场景—能力—验收标准」描述，突出需求如何拆成可交付功能。
- **RAG**: 检索增强生成流程（切分、向量化、检索、重排、生成）；与纯生成对比说明解决幻觉与知识更新问题。
- **BERT vs 大模型**: BERT 偏编码器、判别式、固定任务；大模型偏生成、通用指令跟随；从输入输出讲清 token 化、上下文长度、输出形式差异。

### 二面

**问题清单**:

1. 第一段实习有涉及到系统建设或代码吗
2. 第二段实习承担了什么工作
3. 模型评测怎么做的
4. 模型选型怎么做的
5. 为什么这部分工作交给开发
6. 模型无法正常输出 SQL，运行报错怎么办
7. 论文做的什么，图数据用的什么 Python 库
8. 论文发表情况如何

**参考回答思路**:

- **评测与选型**: 业务指标 + 离线 benchmark + 成本延迟；选型矩阵（场景、数据、合规、团队能力）→ POC → 小规模灰度。
- **分工边界**: PM 定义问题、验收标准与优先级；开发负责实现；说明协作接口（PRD、评测集、bad case 反馈闭环）。
- **SQL 报错排查**: 产品侧先复现与收集日志 → 区分 Prompt/工具链/权限/模型幻觉 → 兜底（规则校验、人工确认、降级模板）；体现跨角色推进而非亲自写代码。
- **学术经历**: 如实讲研究问题与方法；图数据库（NetworkX、PyG 等）按实际使用说明即可。

## 总结与建议

- 科大讯飞该岗位偏 ToB 交付，一面重概念，二面重「能不能跟项目落地与排障」，实习细节要能讲到执行层。
- RAG、评测、选型是高频三连，建议用同一个项目贯穿回答。
- 原帖作者二面未通过，后来者宜加强「故障处理与跨团队协作」的案例准备，而非只背概念。
