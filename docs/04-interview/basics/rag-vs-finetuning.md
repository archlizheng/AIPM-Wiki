# RAG 和微调有什么区别?什么场景该用哪个?

**难度**:⭐⭐ 入门必备
**出现频率**:极高,几乎是 AI PM 面试的"必考题"

## 考察点

- 是否理解两种技术的本质差异(外挂知识 vs 改变模型本身)
- 能否从产品视角(成本、时效、可维护性)做技术选型,而不是只背概念

## 参考答案

**一句话对比**:RAG 是给模型"外挂一个可随时更新的资料库",微调是"把知识和行为模式写进模型本身"。

| 维度 | RAG | 微调 |
|------|-----|------|
| 本质 | 推理时检索外部知识拼进 Prompt | 用领域数据继续训练,改变模型权重 |
| 知识更新 | 改知识库即可,分钟级生效 | 需要重新训练,周期长 |
| 可溯源性 | 天然支持引用来源 | 无法溯源,黑盒 |
| 成本结构 | 建库 + 每次请求的检索开销 | 一次性训练成本 + 数据标注成本 |
| 擅长解决 | 知识类问题(知道什么) | 行为类问题(怎么说、什么格式、什么风格) |

**选型口诀**:
- 知识频繁更新、需要引用来源、私有文档问答 → **RAG**
- 要改变模型的说话风格、输出格式、领域行为习惯 → **微调**
- 两者不互斥:很多产品是"微调过的模型 + RAG"组合

## 追问延伸

- **追问 1**:"RAG 效果不好,你作为 PM 怎么排查?"
  → 拆环节:先看检索(相关材料有没有被找回来),再看生成(找回来了但没答好)。分别对应知识库质量/切片策略问题和 Prompt/模型能力问题。多路召回见 [RAG 系统有哪几种检索路径?](rag-multi-retrieval-paths.md)。
- **追问 2**:"什么情况下你会建议团队既不用 RAG 也不用微调?"
  → 通用能力已够用时,先把 Prompt 优化到极致——成本最低、迭代最快。技术选型应从最轻的手段开始。
- **追问 3**:"微调需要多少数据?"
  → 没有标准答案,重点是答出"取决于任务复杂度,几百到几万条不等;数据质量远比数量重要"。
