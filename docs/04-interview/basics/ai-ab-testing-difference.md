# AI 产品的 A/B 测试和传统产品差在哪？

**难度**:⭐⭐ 常规
**出现频率**:中高，AI PM / 实验与评测向面试常见；选题启发自磊叔《100 个问题》Q54、Q65

## 考察点

- 能否一句话说清：传统 A/B 比的是两种相对确定的体验，AI A/B 比的是两种随机过程
- 是否知道生成方差、新奇效应、离线/线上不对齐会怎么误导结论
- 能否给出可操作的实验设计原则（预注册、分析单元、护栏、离线门 + 线上门），而不是只喊「多跑几天」

## 参考答案

**一句话**：传统产品 A/B 比较的是两种大体确定的体验；AI 产品 A/B 比较的是两种带生成方差的系统——结论要建立在分布差异上，不能靠「某几次好看的回答」。

**差异对照（浓缩）**：

| 维度 | 传统产品 A/B | AI 产品 A/B |
|------|--------------|-------------|
| 处理对象 | UI / 流程 / 规则，体验相对确定 | Prompt / 模型 / 检索 / Agent 策略，输出本身概率 |
| 组内一致性 | 同组用户看到的体验大体一致 | 同组内也可能因采样、上下文、工具结果而差很大 |
| 主要噪声 | 用户异质性、季节性、外生活动 | 上述全部 + **生成方差** + 任务难度长尾 |
| 「改动生效」 | 用户看到了新 UI/新规则 | 用户接触到新系统，但单次输出质量仍在抖动 |
| 离线证据 | 可用性走查、规则回归 | 任务级评测集 / rubric / 安全闸门 |
| 线上主问题 | 用户行为是否因方案而变 | 同上，还要问：行为变了是质量真变好，还是方差/新奇效应？ |
| 护栏 | 崩溃、延迟、核心漏斗 | 再加上拒答、幻觉/安全、转人工、单位任务成本等 |
| 可复现性 | 回放同一 UI 即可对照 | 固定模型版本与采样设置，或接受「分布可比」而非「逐字可比」 |

**答题时再补三条原则（面试官爱听「怎么做」）**：

1. **预注册假设、OEC、护栏与停止规则**：写清改了什么、预期改善哪类任务、主指标分子分母与触发人群、安全/成本一票否决、计划样本量——别「看着涨了就推全」。
2. **显式处理生成随机性**：固定模型版本与采样参数；线上以用户/会话为分析单元，不要拿单次生成当独立样本宣称胜负；离线同一用例可多跑看均值与波动。
3. **离线质量门 + 线上因果门**：离线未过安全/质量闸门不进正式 A/B；线上显著要回看离线分维度是否同向；冲突先查分布漂移与指标定义。另为新奇效应留观察窗口（按曝光天数看 lift 是否衰减），样本量用自家历史方差估，不套外部「经验天数」。

**场景举例**：客服改 Prompt 后，B 组前两天「多聊几轮、点赞变多」——可能是新奇，也可能是回答变长被误当成成功。应预注册「一次解决率 / 转人工率」作 OEC，护栏看延迟与成本；分析按会话聚合；同时对照离线评测集是否同向提升。细节与清单见正课。

## 追问延伸

- **追问 1**：「离线评测涨了、线上业务不动，你怎么查？」
  → 评测集与线上分布不一致；入口/展示/信任没触达；延迟或成本拖垮体验。反过来「线上涨、离线不动」优先怀疑新奇效应、外生活动、或「多聊」被误当成功。
- **追问 2**：「AI 实验是不是一定要更大样本 / 更久？」
  → 往往方差更高，**可能**需要更长窗口或更大流量，但没有行业统一倍数；用历史方差与 MDE 算功效，并检查新奇是否衰减。
- **追问 3**：「evals 能不能替代 A/B？」
  → 不能互相替代：evals 看任务表现，A/B 看真实用户与业务因果；官方实践也强调二者互补。上线链路默认是离线门 → 灰度 → 正式 A/B → 对齐解释。
