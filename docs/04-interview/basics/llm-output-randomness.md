# 为什么大模型的输出每次都不一样?

**难度**:⭐ 入门
**出现频率**:中,仓库规划题

## 考察点

- 能否解释大模型输出的概率本质
- 是否理解 Temperature 等参数的作用
- 能否从产品角度说明何时需要确定性、何时需要多样性

## 参考答案

**一句话解释**:大模型是概率模型,每次生成时对每个候选 token 做"加权随机抽样",而非查表返回固定答案。

**原理简述**:
1. 模型输出的是下一个 token 的概率分布(如"好"30%、"行"25%、"的"20%...)
2. 采样策略从分布中抽取一个 token 作为输出
3. 每抽一次,后续所有 token 的概率都会变化(因为上下文变了)
4. 因此即使输入完全相同,输出也可能不同

**影响随机性的关键参数**:

| 参数 | 作用 | 值越高 | 值越低 |
|------|------|--------|--------|
| Temperature | 控制概率分布的"平坦度" | 输出更多样、更有创意 | 输出更确定、更保守 |
| Top-p | 只从概率累计前 p 的 token 中采样 | 候选范围更大 | 候选范围更小 |
| Seed | 固定随机种子 | — | 相同输入可复现相同输出 |

**产品场景选择**:

| 场景 | 随机性需求 | 参数建议 |
|------|-----------|----------|
| 客服问答、知识查询 | 低,要稳定一致 | 低 Temperature |
| 创意写作、头脑风暴 | 高,要多样新颖 | 高 Temperature |
| 代码生成、格式输出 | 低,要精确合规 | 低 Temperature + 格式约束 |
| A/B 测试 | 可控 | 固定 Seed 保证可复现 |

**用户预期管理**:产品层面应告知用户"AI 回答仅供参考",关键场景提供"重新生成"和"固定回答"选项。

## 追问延伸

- **追问 1**:"用户抱怨'同一个问题每次答案不一样',你怎么处理?"
  → 降低 Temperature;对高频问题做缓存;提供"标准回答"模式;向用户解释 AI 的随机性特征。
- **追问 2**:"什么场景下随机性是优势?"
  → 创意生成(避免千篇一律)、探索式对话(每次有新角度)、生成评测集的多样化样本。
- **追问 3**:"怎么在开发测试时保证结果可复现?"
  → 固定 Seed 值;降低 Temperature 到 0(贪婪解码);用固定的测试集和参数跑回归。
