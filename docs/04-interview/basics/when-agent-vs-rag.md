# 企业知识库问答和 Coding Agent,检索架构该怎么选?

**难度**:⭐⭐⭐ 进阶
**出现频率**:中高,Agent 平台、RAG 产品二面常见,考察架构选型而非背概念

## 考察点

- 能否区分"固定流水线"和"Agent 动态调用工具"两种架构范式的适用边界,而不是无脑站队
- 是否会主动考虑多用户权限、成本、可观测性这几个容易被忽略的产品维度
- 能否给出可落地的判断标准,而不是泛泛而谈"看场景"

## 参考答案

**一句话**:企业知识库问答优先选**稳定可控的 Hybrid RAG**,Coding Agent 优先选**Agent + 动态工具(grep/向量检索/AST 解析等由模型自己选)**,分歧点在任务形态和风险容忍度,不在于"哪个技术更先进"。

### 两种架构范式对比

| 维度 | 稳定 Hybrid RAG | Agent + 动态工具 |
|------|-----------------|-------------------|
| 任务形态 | 单跳/少跳,问题类型稳定(FAQ、制度问答) | 多步骤,需要"查一次看结果再决定下一步"(排障、跨文件改动) |
| 检索方式 | 系统预先配置好向量 + BM25 + 重排,规则固定 | 模型自主选择 grep / 向量检索 / AST 解析 / 执行测试等 |
| 可预测性 | 高,每次请求路径一致,方便压测和 SLA | 低,步数和路径依任务而变,尾延迟/成本波动大 |
| 多用户权限 | 权限过滤在检索前完成,规则集中、易审计(按租户过滤索引) | 工具调用需逐次鉴权,权限模型更分散,要防止 Agent 被诱导越权读取 |
| 成本结构 | 单次请求成本可预估(固定路数 × 固定 Top-K) | 成本随任务步数浮动,复杂任务可能多轮调用工具,难以提前定价 |
| 可观测性 | 单一链路,日志结构统一,故障容易定位到"检索"或"生成" | 多步决策链,需要完整执行轨迹追踪(Agent Ops),出错要看每一步中间态才能定位 |
| 典型代表 | 企业 FAQ、客服知识库、政策问答 | Claude Code / Codex 类 Coding Agent,多步代码排障 |

### 为什么这么分

- **企业知识库问答不选 Agent**:问题分布相对稳定,用户提问模式重复度高,固定 Hybrid RAG 的可预测性和低成本优势明显;而且企业场景往往有严格的多租户权限要求,把过滤规则写在检索前,比让 Agent 每次自己判断"这条我能不能看"更安全、更容易审计。
- **Coding Agent 不选纯 RAG**:代码仓库的"证据"分散在文件结构、符号引用、测试结果里,固定向量检索很难覆盖"这个函数被哪里调用""这次改动会不会破坏测试"这类需要"查一次看结果再查下一次"的任务,Agent 自主决定工具调用顺序是必要能力,不是可选项。
- **混合地带更常见**:不是所有产品都要二选一。同一个产品可以对"简单 FAQ"走固定 Hybrid RAG,对"复杂工单"路由给带工具调用能力的 Agent,用查询分类做前置路由,让检索本身在 Agent 内部降级为可调用工具之一。

### 给 AI PM 的判断框架

1. **任务是否天然多步骤**——单跳可回答的问题,别为追新引入 Agent 的不确定性和调试成本。
2. **权限模型是集中还是分散**——多租户要求越严格,越应该让权限过滤发生在检索前,而不是依赖 Agent 自觉。
3. **能否承受成本和延迟的不确定性**——固定流水线成本可预估,Agent 多轮工具调用的成本和时延都可能有长尾。
4. **出错之后能不能定位**——引入 Agent 前先确认有完整的执行轨迹追踪能力,否则出问题会很难排查。

## 追问延伸

- **追问 1**:"两种架构可以同时存在于一个产品里吗?"
  → 可以,而且是主流做法:用查询路由先分流,简单问题走 Hybrid RAG,复杂/多步骤问题路由给 Agent,Agent 内部再把检索当成众多工具之一调用。
- **追问 2**:"企业知识库要不要也上 Agentic 检索?"
  → 取决于问题类型是否混杂难预判:如果用户提问形态高度多样(有时一句话能答,有时要跨多文档综合),Agentic Retrieval 的价值才会显现;否则固定 Hybrid RAG 的确定性收益更大。
- **追问 3**:"怎么防止 Agent 在多用户场景下越权读取?"
  → 工具调用层做逐次鉴权(不能只在入口做一次全局校验),文件/索引按租户物理或逻辑隔离,高风险读取动作留执行日志,便于事后审计。
