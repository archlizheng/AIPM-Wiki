# 离线 Evals 全绿、线上「时灵时不灵」，Gap 怎么填？

**难度**:⭐⭐⭐ 进阶
**出现频率**:高，评测 / Agent / 实验向 AI PM 面试常见；选题启发自磊叔《100 个问题》相关评测题（与正课 C6 同族）

## 考察点

- 能否一句话说清：离线全绿 ≠ 线上稳定好用，Gap 来自分布、指标、链路、方差或过拟合
- 是否能给出可操作的排查优先级，而不是只抱怨「用户太挑剔」或「再加几条 case」
- 是否知道用「离线质量门 → 灰度/影子 → 线上行为/OEC」闭环把 Gap 补上，并与 A/B 原则对齐

## 参考答案

**一句话**：离线报表绿、线上时灵时不灵，通常是离线世界与线上世界脱节——评测分布、评测维度、链路瓶颈或生成方差与真实用户不一致；填 Gap 靠对齐指标、回流真实负向会话、多 trial 看稳定性，再用灰度与正式 A/B 验证业务因果。

**先拆五类常见根因（面试官爱听「怎么查」）**：

| 根因 | 表现 | 排查动作 |
|------|------|----------|
| 评测分布 ≠ 线上分布 | 集子是干净规范问法；用户是方言、错别字、多意图揉一起 | 按线上频率分桶重采样；长尾单独建切片 |
| 评测维度 ≠ 用户价值 | Evals 涨在流畅度/格式；用户要一次办成、可复制、可信任 | 把采纳、完成、转人工等行为指标与分维度 eval 对齐 |
| 链路瓶颈不在模型 | 模型分涨了，检索/权限/兜底/UI 仍卡住 | 按链路分段看「模型层改善是否触达用户可见结果」 |
| 方差被当成稳定质量 | 单次跑分全绿；线上同一任务时好时坏 | 离线多 trial；线上按用户/会话聚合看分布 |
| 过拟合评测集 | 对着同一批 case 调到满分 | 保留 held-out；新日志持续进集；能力集与回归集分开 |

**离线涨了、业务不动（Gap 的反向版）——排查顺序**：

1. **指标翻译是否对齐**：离线主指标是否映射到预注册的线上 OEC / 护栏？不对齐就先改评测定义，而不是加流量。
2. **散点对照**：几次版本变更的离线分 vs 线上行为/业务指标；长期不相关，说明在优化错误目标。
3. **触达检查**：灰度用户是否真打到新版本？缓存、路由、客户端旧包是否稀释效果？
4. **体验摩擦**：延迟、确认弹窗、格式变化是否抵消质量收益？

**默认闭环（可背成答题骨架）**：

```text
离线评测集 + 安全闸门
  → 小流量 / 影子观察质量与稳定性
  → 正式 A/B（用户随机，预注册 OEC + 护栏）
  → 结论与离线分维度对照；负向会话脱敏回流评测集
```

离线回答发版前「系统还行不行」；线上回答发版后「用户感受到了什么」。除了报错率，优先看拿到回答后的下一步：复制/采纳、追问并完成、立即重生成、关闭、转人工。

**场景举例**：知识库助手离线「事实正确率」全绿，线上客诉「有时答对有时胡说」。查下来：评测集全是标准 FAQ，线上 40% 流量是多意图口语；且只跑了单次 trial。动作：按线上意图桶补切片 + 多 trial 报成功率分布；把「一次解决 / 转人工」挂成 OEC；坏会话回流 held-out；未过闸不扩量。

细节与清单见正课[线下绿、线上灰](../../02-pm-skills/ai-product-operations/agent-evaluation-and-observability.md)与[AI 产品的 A/B 测试](../../02-pm-skills/model-evaluation/ab-testing-for-ai-products.md)。

## 追问延伸

- **追问 1**：「evals 能不能替代线上 A/B？」
  → 不能互相替代：evals 看任务表现与规格，A/B 看真实用户与业务因果；官方实践也强调互补。离线未过安全/质量闸门，不进正式 A/B。
- **追问 2**：「怎么证明不是生成方差在骗人？」
  → 离线同一用例多跑，报告均值与波动，而不是单次绿灯；线上以用户/会话为分析单元；固定模型版本与采样参数，接受「分布可比」而非「逐字可比」。
- **追问 3**：「没有 golden set / 刚上线就喊时灵时不灵，怎么办？」
  → 先用真实轨迹抽样建种子集（脱敏），再固化可重复 dataset；行为哨兵（重生成、转人工、完成率）与质量哨兵（回归集 + 抽样回放）并行，不等投诉堆满再补评测。
- **追问 4**：「供应商悄悄升版会不会造成这种 Gap？」
  → 会。接口未变 ≠ 行为未变。生产钉死可回滚版本 ID；升版触发固定回归集 + 场景桶对比 + 影子回放；效果分涨但护栏爆了仍不放行。
