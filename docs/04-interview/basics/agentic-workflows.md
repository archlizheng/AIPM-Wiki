# 什么是 Agentic Workflows?

**难度**:⭐⭐ 进阶
**出现频率**:高,大厂常见题、字节面经均有出现

## 考察点

- 能否区分 Agentic Workflows 和传统自动化工作流的本质差异
- 是否理解 LLM 在工作流中扮演的"决策节点"角色
- 能否结合产品场景说明适用边界

## 参考答案

**一句话定义**:Agentic Workflows 是由 AI Agent 驱动的自动化工作流——LLM 不仅执行任务,还负责理解目标、规划步骤、动态调整路径。

**与传统工作流的对比**:

| 维度 | 传统工作流 | Agentic Workflows |
|------|-----------|-------------------|
| 步骤定义 | 人工预设,固定路径 | AI 动态规划,可调整 |
| 分支逻辑 | if-else 规则 | LLM 理解上下文后决策 |
| 异常处理 | 预设兜底分支 | Agent 尝试自我修正 |
| 灵活性 | 低,改流程需改代码 | 高,改 Prompt 即可调整行为 |
| 可控性 | 高,每步可预期 | 较低,存在不确定性 |

**典型架构**:
```
用户目标 → Agent 规划步骤 → 调用工具/API → 检查中间结果
                ↑                                    |
                └──── 结果不理想? 重新规划 ←──────────┘
```

**适用场景**:
- 步骤不固定、需根据中间结果调整的任务(如调研报告生成)
- 需要理解和判断的自动化(如客服工单分类 + 路由)
- 跨多个工具/API 的复杂流程编排

**不适用场景**:
- 步骤严格固定、零容错的流程(如支付) → 用传统工作流
- 简单重复任务 → 过度工程化

**产品视角**:Agentic Workflows 是 Agent 能力的工程化落地形态。PM 需要定义:哪些步骤交给 AI 决策、哪些步骤必须人工确认、出错时的回退策略。

## 追问延伸

- **追问 1**:"Agentic Workflows 和 RAG 是什么关系?"
  → 互补:RAG 解决"知识从哪来",Agentic Workflows 解决"任务怎么做"。很多 Agent 工作流中,检索是其中一个工具调用环节。
- **追问 2**:"怎么控制 Agentic Workflows 的成本?"
  → 限制最大步骤数、设置工具调用预算、简单任务走固定流程、复杂任务才触发 Agent 模式。
- **追问 3**:"工作流中某一步 Agent 做错了怎么办?"
  → 设计检查点(checkpoint):关键步骤需人工确认;自动重试 + 降级到规则逻辑;记录完整执行日志便于排查。
