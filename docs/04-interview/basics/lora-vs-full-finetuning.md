# LoRA 和全量微调有什么区别?什么场景选哪个?

**难度**:⭐⭐ 进阶
**出现频率**:高,抖音校招面经出现

## 考察点

- 能否讲清 LoRA 的核心原理(低秩适配,只训练少量参数)
- 是否理解两者在成本、效果、灵活性上的权衡
- 能否结合团队资源和业务需求做选型判断

## 参考答案

**一句话对比**:全量微调是"重新培训整个员工",LoRA 是"只培训关键技能模块"。

| 维度 | 全量微调 | LoRA |
|------|----------|------|
| 训练参数量 | 全部模型参数 | 仅少量低秩矩阵(通常 <1%) |
| 显存/算力需求 | 高,需要多卡 | 低,单卡可完成 |
| 训练速度 | 慢 | 快 |
| 效果上限 | 更高,尤其复杂任务 | 多数场景接近全量,极端场景有差距 |
| 多任务切换 | 每个任务需完整模型副本 | 可热切换不同 LoRA 适配器 |
| 灾难性遗忘 | 风险较高 | 风险较低,基座能力保留好 |

**选型口诀**:
- 数据量大(万级以上)、任务复杂、追求极致效果 → **全量微调**
- 资源有限、需要快速迭代、多任务并行 → **LoRA**
- 大多数产品团队的现实选择 → **LoRA**,性价比最高

**产品视角**:PM 不需要会实现 LoRA,但需要知道"团队只有一张 GPU"时 LoRA 是合理选择;"要同时服务 10 个垂直场景"时 LoRA 的多适配器切换是优势。

## 追问延伸

- **追问 1**:"LoRA 效果不如全量微调时你怎么决策?"
  → 看业务指标差距是否显著:如果 LoRA 已满足上线标准,优先快速迭代;差距影响核心指标再考虑全量。
- **追问 2**:"微调数据和基座模型选型,哪个更重要?"
  → 数据质量 > 数据数量 > 基座选型;好数据配中等模型,往往比差数据配顶级模型效果好。
- **追问 3**:"LoRA 适配器怎么管理多个业务场景?"
  → 一个基座 + 多个 LoRA 权重,按场景路由加载;类似"一个通用员工 + 多套岗位技能包"。
