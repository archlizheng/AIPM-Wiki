# AI 产品中如何平衡准确性与响应速度?

**难度**:⭐⭐ 入门必备
**出现频率**:高,JD 押题、大厂常见题均有出现

## 考察点

- 能否识别准确性和延迟之间的结构性张力
- 是否理解不同场景对两者的容忍度差异
- 能否给出产品层面的权衡策略,而非只说"都要"

## 参考答案

**核心矛盾**:提升准确性往往意味着更多计算(更大模型、更多检索、多轮推理),而用户等待耐心有限。两者不是简单的此消彼长,而是需要在场景层面做取舍。

**场景分级策略**:

| 场景类型 | 准确性要求 | 延迟容忍 | 策略 |
|----------|-----------|----------|------|
| 高风险决策(医疗/金融) | 极高 | 可等几秒 | 优先准确性,用 Rerank、多轮验证 |
| 实时交互(客服/搜索) | 中高 | 1-3 秒 | 平衡,可用小模型 + RAG 组合 |
| 批量处理(报告生成) | 高 | 分钟级可接受 | 准确性优先,异步处理 |
| 创意辅助(写作/脑暴) | 中 | 越快越好 | 延迟优先,快速出草稿 |

**产品权衡手段**:
1. **分层响应**:先快速返回简要回答,后台继续深度检索后补充
2. **场景路由**:简单问题走轻量链路,复杂问题走完整链路
3. **用户预期管理**:展示"正在深度分析..."等状态,降低等待焦虑
4. **缓存策略**:高频问题预生成答案,牺牲一定时效换速度

**回答框架**:先问"这个场景的用户愿意等多久",再问"答错的代价有多大",在两个约束下找最优平衡点。

## 追问延伸

- **追问 1**:"RAG 加了检索之后延迟明显上升,你怎么优化?"
  → 检索链路优化(索引加速、减少召回量)、结果缓存、异步预检索、按问题复杂度动态选择检索深度。
- **追问 2**:"用户反馈'回答太慢',你怎么判断是延迟问题还是准确性不够?"
  → 看数据:跳出率、中途取消率、满意度与响应时间的相关性;必要时做延迟 vs 准确性的 A/B 测试。
- **追问 3**:"流式输出能缓解延迟问题吗?"
  → 能改善感知延迟(首 token 时间),但总生成时间不变;适合长回答场景,短回答意义不大。
