# 如果你是某 AI 搜索产品的 PM,你的北极星指标是什么?

**难度**:⭐⭐⭐ 进阶
**出现频率**:高,常见于搜索/问答类 AI 产品岗位

## 考察点

- 是否理解北极星指标要同时满足"能代表用户价值"和"能被团队各环节影响"两个条件
- 能否区分 AI 搜索与传统搜索在指标体系上的本质差异(答案型 vs 链接列表型)
- 是否会用**指标树**而非单一指标解释复杂产品,同时依然能收敛出一个北极星

## 参考答案

**一句话核心**:AI 搜索的北极星指标应该是**「一次问答解决问题率」**(Task Success in One Turn,或类似的「有效解决率」),而不是传统搜索沿用的点击率或搜索量。

### 第一步:说明为什么不能照搬传统搜索的指标

| 传统搜索指标 | 为什么不适用 AI 搜索 |
|--------------|----------------------|
| 点击率(CTR) | AI 搜索的目标是"直接给答案",高点击率反而可能说明答案不够好、用户还要点进去验证 |
| 搜索量 / DAU | 反映活跃度但不反映"问题有没有被解决",容易被无效重复搜索污染 |
| 停留时长 | 停留久可能是答案难懂、要反复琢磨,不是正向信号 |

### 第二步:定义候选北极星指标

**一次问答解决问题率**:用户发起一次提问,得到答案后没有立刻改写问题重新提问、没有转向传统搜索/其他渠道、且在合理时间内没有回来追问同一问题——即视为"被解决"。

可以用三个维度交叉验证是否被解决:
1. **行为信号**:是否有追问/改写(负向)、是否复制/分享答案(正向)
2. **显式反馈**:点赞/点踩、引用来源是否被点开核实
3. **留存信号**:该类问题在后续是否重复出现(说明没被真正解决)

### 第三步:搭建指标树,支撑北极星指标

```
一次问答解决问题率(北极星)
├── 答案质量:准确率、幻觉率、引用可信度
├── 覆盖能力:有答案 vs "不知道"的比例、长尾问题覆盖率
├── 效率体验:首字延迟、完整答案生成时长
└── 信任建立:引用点击率、反馈参与率
```

这样团队里不同角色都能找到自己的抓手:算法团队盯准确率和幻觉率,工程团队盯延迟,产品团队盯反馈机制设计——但对外汇报时收敛为一个北极星,不让指标体系变成"既要又要"的借口。

### 第四步:说明指标会随阶段调整

- **冷启动期**:先看「覆盖率」和「有答案率」,不追求极致准确,先解决"有没有"的问题
- **成长期**:切换到「一次解决率」,开始关注答案质量和用户信任
- **成熟期**:叠加「留存/回访率」,证明用户把它当作稳定的信息获取入口而非一次性尝试

## 追问延伸

- **追问 1**:"这个指标怎么防止被"刷"出来?"
  → 说明反作弊设计:结合行为信号交叉验证(如同一用户短时间内相似 query 判定为未解决),避免只依赖单一显式反馈(点赞可被诱导)。
- **追问 2**:"如果解决率提升了,但用户量在下降,你怎么看?"
  → 说明北极星指标不能单独看,要配合「护栏指标」(如 DAU、留存)一起监控;解决率提升可能是筛掉了低质量流量,需要拆分新老用户、不同问题类型来定位原因。
- **追问 3**:"这个指标怎么和商业化目标结合?"
  → 解决率是先决条件——用户觉得"有用"才会留存和付费;可以进一步拆分「高价值问题解决率」(如专业咨询类)作为商业化转化的前置指标。
