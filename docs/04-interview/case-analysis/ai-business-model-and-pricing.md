# DeepSeek 开始峰谷定价,你怎么看 AI 产品的商业模式?

**难度**:⭐⭐⭐ 进阶
**出现频率**:中,常见于战略/商业化方向或偏 ToB 的 AI PM 岗

## 考察点

- 能否从**成本结构、用户行为、竞争格局**三个维度分析 AI 产品定价,而非只评论"便宜/贵"
- 是否理解峰谷定价背后的供需逻辑,以及它对产品设计和用户运营的连锁影响
- 能否提出可落地的商业模式框架,而不是泛泛而谈"按量付费"

## 参考答案

**一句话核心**:AI 产品的商业模式本质是**把不确定的推理成本转化为可预期的用户价值**,峰谷定价是成本侧波动向定价侧传导的必然产物,PM 要关注的是它如何重塑产品形态和用户行为。

### 框架一:AI 产品的成本结构拆解

```
总成本 = 模型推理成本 + 基础设施 + 研发摊销 + 数据/标注 + 客户获取
```

其中**模型推理成本**有几个独特属性:
- **按 token 线性增长**,不像传统 SaaS 的边际成本趋近于零
- **随模型能力升级而上升**,同样任务可能因换模型而成本翻倍
- **存在明显的时间波动**:算力供需、批处理 vs 实时推理、缓存命中率

峰谷定价的本质:把**供给侧的成本波动**通过价格信号传导给需求侧,引导用户在低成本时段使用。

### 框架二:常见 AI 产品商业模式对比

| 模式 | 逻辑 | 适合场景 | 风险 |
|------|------|----------|------|
| 按量计费(token/次) | 成本与收入线性挂钩 | API 平台、开发者工具 | 用户成本不可预期,大客流失 |
| 订阅制(含额度) | 可预期收入,额度内包干 | ToC 助手、ToB SaaS | 重度用户可能"薅羊毛" |
| Freemium + 增值 | 免费获客,付费解锁能力 | 消费级 AI 应用 | 免费层成本需严格控制 |
| 峰谷/动态定价 | 削峰填谷,优化算力利用率 | 算力平台、非实时任务 | 用户体验复杂度上升 |
| 效果付费 | 按业务结果收费 | 营销文案、客服替代 | 归因难,合同复杂 |

### 框架三:峰谷定价对产品的影响

**对用户侧**:
- 非实时任务(文档总结、批量翻译、代码审查)可引导至低谷时段,降低用户成本
- 实时对话类场景难以错峰,需在定价和产品体验间做取舍
- 产品可增加"定时任务""排队处理"等功能承接低谷流量

**对 PM 的设计启示**:
1. **功能分层**:实时 vs 异步,对应不同定价档位
2. **额度设计**:订阅包含基础额度 + 峰谷差价返还/积分
3. **成本可视化**:让用户看到"此刻调用成本",培养错峰习惯(B 端尤其有效)
4. **缓存与复用**:相同 query 命中缓存,成本趋近于零,可不对用户重复计费

### 框架四:竞争格局下的战略选择

| 阶段 | 典型策略 |
|------|----------|
| 市场教育期 | 补贴换规模,定价不是核心变量 |
| 差异化期 | 按场景/效果分层,而非单纯价格战 |
| 成熟期 | 成本优化 + 生态锁定(模型 + 工具链 + 数据飞轮) |

**回答收束**:峰谷定价不是简单的"晚上便宜",而是 AI 产品从"软件逻辑"转向"资源调度逻辑"的信号。PM 应思考:哪些功能可以异步化?如何用产品机制让用户自愿错峰?如何在定价透明度与商业灵活性之间平衡?

## 追问延伸

- **追问 1**:"如果你是某 AI 写作产品的 PM,你会怎么设计定价?"
  → 拆用户场景:即时写作(高峰、高单价) vs 批量润色(可异步、低谷);订阅含月额度,超额按量;企业版按席位 + 共享额度池。
- **追问 2**:"用户抱怨成本不可预期,你怎么解决?"
  → 产品侧:成本预估器、消费上限告警、缓存复用;商业侧:包月封顶、预付费折扣;技术侧:小模型路由 + 大模型兜底。
- **追问 3**:"开源模型越来越便宜,闭源 API 怎么活?"
  → 卖的不只是模型:稳定性、合规、工具链、微调服务、SLA;或转向垂直场景的整体解决方案,而非裸 API。
- **追问 4**:"订阅、Token、按结果三种,你怎么选?"
  → 按决策树走:有履约中台优先交易;要账单可预期走订阅/席位+用量;结果可归因再试点按结果;对 C 端慎透传裸 Token。完整树见正课。
