# 模型准确率从 90% 提升到 95%,对业务价值如何量化?

**难度**:⭐⭐⭐ 进阶
**出现频率**:高,常见于有算法/数据背景的团队或 B 端 AI 产品岗

## 考察点

- 能否把技术指标翻译成业务语言,而不是停留在"准确率提升了 5 个百分点"
- 是否会用**基线 → 拆解 → 估算 → 验证**的框架做价值量化
- 是否理解准确率提升的边际收益递减,以及不同业务场景下"5%"的含义完全不同

## 参考答案

**一句话核心**:准确率提升的价值 = 在**错误成本 × 业务量 × 错误率变化**的框架下,算清"少错了多少、每少错一次值多少钱",再减去模型升级成本。

### 第一步:明确"准确率"的定义

面试中先澄清口径,体现严谨性:

| 需澄清项 | 为什么重要 |
|----------|------------|
| 准确率 vs 精确率 vs 召回率 | 90%→95% 可能是精确率提升(少误杀),也可能是召回率提升(少漏检),业务含义不同 |
| 按什么粒度统计 | 按请求、按用户、按订单?不同粒度下 5% 对应的绝对数量差很大 |
| 基线场景 | 是整体准确率还是某个关键子场景的准确率 |

### 第二步:拆解业务影响链路

```
模型输出 → 人工/系统决策 → 用户行为 → 业务结果(收入/成本/风险)
```

按场景举例:

**场景 A:智能客服意图识别(90%→95%)**
- 错误一次 ≈ 转人工或用户流失
- 价值估算:
  - 日请求量 100 万 × 错误率从 10% 降到 5% = 每天少错 5 万次
  - 假设 30% 转人工,单次人工成本 3 元 → 日省 5万×30%×3 = **4.5 万元/天**
  - 再叠加用户流失挽回(需用 A/B 实验验证)

**场景 B:内容审核(90%→95% 精确率)**
- 提升的是"误杀率"下降,价值在于减少优质内容被错误拦截
- 价值 = 少误杀条数 × 单条内容预期 GMV/曝光价值

**场景 C:信贷风控(90%→95% 召回率)**
- 提升的是"漏放"减少,价值 = 少漏放笔数 × 单笔预期坏账损失

### 第三步:建立量化公式

```
业务价值 ≈ Δ错误数 × 单次错误成本 + Δ正确带来的增量收益 - 模型升级成本
```

其中:
- **Δ错误数** = 业务量 × (旧错误率 - 新错误率)
- **单次错误成本**需分 direct cost(人工、赔付)和 indirect cost(流失、品牌)
- **模型升级成本** = 算力 + 标注 + 研发人天 + 延迟增加带来的体验损失

### 第四步:给出结论框架(而非精确数字)

| 维度 | 90% | 95% | 价值判断 |
|------|-----|-----|----------|
| 错误绝对量(百万日请求) | 10 万/天 | 5 万/天 | 减半,价值显著 |
| 错误绝对量(万级日请求) | 1000/天 | 500/天 | 需看单次错误成本是否够高 |
| 已接近人工水平(98%+) | 2% 错误 | 更优 | 边际价值可能不如优化长尾场景 |

**PM 应给出的结论**:不是"95% 一定更好",而是"在 XX 业务量、XX 错误成本假设下,ROI 为正/需实验验证/不如把资源投到召回率"。

## 追问延伸

- **追问 1**:"如果老板只关心准确率数字,你怎么沟通?"
  → 用一页纸把技术提升映射到业务指标(转人工率、客诉率、审核通过率),建议用 A/B 实验让数据说话,而不是争论百分点。
- **追问 2**:"95% 还不够,业务要求 99%,你怎么排优先级?"
  → 分析剩余错误的分布:是否集中在长尾/边缘 case?是否可以通过规则兜底 + 人工复核达到更高的**有效准确率**,而不必把模型裸分推到 99%?预期管理与代价拆解见正课 [主观任务怎么评 · 90→99 预期管理](../../02-pm-skills/model-evaluation/llm-as-a-judge.md#老板要准确率-9099怎么管理预期)。
- **追问 3**:"准确率提升了,但延迟也增加了 200ms,怎么权衡?"
  → 把延迟纳入成本侧:用体验指标(跳出率、完成率)量化延迟损失,与准确率收益做净价值比较。
