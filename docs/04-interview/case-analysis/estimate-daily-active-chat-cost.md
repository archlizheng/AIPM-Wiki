# 估算日活 100 万的 AI 对话产品每月模型调用成本

**难度**:⭐⭐ 常规
**出现频率**:极高,字节/美团/快手等大厂 AI PM 面经高频出现

## 考察点

- 能否把开放性问题拆解为**可假设、可计算**的参数
- 是否理解 token 计费逻辑,以及影响成本的关键变量(模型选型、对话轮次、上下文长度)
- 估算不要求精确,但要求**假设合理、计算过程清晰、能主动说明敏感性**

## 参考答案

**一句话核心**:月成本 ≈ DAU × 人均日对话轮次 × 每轮 token 数 × 每 token 单价 × 30 天,关键是把每个参数拆开并给出合理假设。

### 第一步:明确产品形态(先问清 or 主动假设)

面试中可主动设定场景,体现结构化思维:

> 假设这是一个 ToC AI 助手(类似 ChatGPT 移动端),用户以多轮文本对话为主,使用某个中等能力模型。具体型号、区域和计费档位应在估算时引用 [LLM 成本测算主文](../../02-pm-skills/cost-and-tech/llm-cost-101.md) 的当日官方快照或合同。

### 第二步:参数拆解与假设

| 参数 | 假设值 | 依据 |
|------|--------|------|
| DAU | 100 万 | 题目给定 |
| 活跃率(占注册用户) | — | 题目给的是 DAU,直接用 |
| 人均日对话轮次 | 8 轮 | 参考 ChatGPT 类产品的中等活跃度 |
| 每轮输入 token | 800 | 含系统 Prompt(~200) + 历史上下文(~400) + 用户当轮输入(~200) |
| 每轮输出 token | 300 | 中等长度回复 |
| 每轮总 token | 1100 | 输入 + 输出 |
| 模型单价(混合) | ~$0.5 / 1M tokens | 本题教学占位假设；实际值按当日官方价目或合同填入，不代表市场均价 |

**注意**:一定要分开算输入和输出。不同模型、处理档位、缓存或 Batch 条件的输入/输出价格不同，按主文当日快照替换下面的教学占位值。更精细的估算:

| 项目 | token 数 | 单价(假设) | 费用 |
|------|----------|------------|------|
| 输入 | 800 | $0.15/1M | — |
| 输出 | 300 | $0.60/1M | — |
| 每轮合计 | 1100 | 加权 ~$0.35/1M | ~$0.00038/轮 |

### 第三步:计算过程

```
日总轮次 = 1,000,000 DAU × 8 轮/人 = 8,000,000 轮/天
日总 token = 8,000,000 × 1,100 = 8.8B tokens/天
月总 token = 8.8B × 30 = 264B tokens/月

月模型成本(粗算) = 264B × $0.5/1M ≈ $132,000/月 ≈ 95 万人民币/月
```

更精细(区分输入输出):
```
月输入 token = 264B × (800/1100) ≈ 192B → 192,000 × $0.15 ≈ $28,800
月输出 token = 264B × (300/1100) ≈ 72B  → 72,000 × $0.60  ≈ $43,200
月合计 ≈ $72,000/月 ≈ 52 万人民币/月
```

**给出区间比精确数字更重要**:"在以上题设参数和教学价格假设下,月模型成本约为 **50 万 - 130 万** 人民币；真实区间应由模型价格、用户活跃度和上下文分布重新计算。"

### 第四步:成本构成扩展(加分项)

模型推理不是全部成本,完整估算应提及:

| 成本项 | 估算思路 | 量级(相对模型) |
|--------|----------|----------------|
| 模型推理 | 上述计算 | 100% |
| Embedding / RAG 检索 | 按实际嵌入、重排和检索服务价目及调用量估算 | 另行测算 |
| 向量数据库 | 按存储、查询量和服务价目估算 | 另行测算 |
| 缓存命中 | 按实际命中率、缓存计费规则和命中请求的输入输出量测算 | 另行测算 |
| 小模型路由 | 按路由比例、各模型官方价格和质量门槛测算 | 另行测算 |
| GPU 自部署 vs API | 大规模时自部署可能更便宜 | 视规模而定 |

### 第五步:敏感性分析(体现 PM 思维)

以下是基于本题参数的敏感性演算示例，不是行业经验比例；实际值需用日志、账单和实验结果替换。

| 变量变化 | 成本影响 |
|----------|----------|
| 人均轮次 8→15 | 成本约 ×1.9 |
| 换用旗舰模型(单价 ×10) | 成本约 ×10 |
| 上下文从 800→3000 input token | 成本约 ×2.5 |
| 缓存命中率 30% | 成本约 ×0.7 |

**结论**:在本题的 DAU、轮次、token 和教学价格假设下，月模型成本落在上述演算区间；不能据此概括真实产品的成本量级。成本优化应优先关注**上下文长度管理、模型分级路由、缓存**三个可测杠杆。

## 追问延伸

- **追问 1**:"老板觉得成本太高,你会从哪几个方向降本?"
  → 模型分级(简单问题走小模型)、Prompt 压缩(减少历史上下文)、缓存(高频问题)、限制免费用户轮次/上下文。详见 [降本专题](reduce-llm-cost-10x.md)。
- **追问 2**:"你怎么估算人均 8 轮,而不是 3 轮或 20 轮?"
  → 说明数据来源:可参考公开 benchmark、同类产品的留存/时长数据、或自己产品的历史数据;给出区间并做敏感性分析。
- **追问 3**:"如果加上图片/语音多模态,成本怎么变?"
  → 图片、语音等按各自服务和模型的当前计费方式估算；不要套用固定倍数，需单独记录渗透率、频次、输入输出量和失败重试成本。
