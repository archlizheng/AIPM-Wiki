# 某功能接入大模型后成本涨了 10 倍,如何降本?

**难度**:⭐⭐⭐ 进阶
**出现频率**:高,考察实战思维和成本意识

## 考察点

- 能否系统性拆解 LLM 成本构成,而不是只说"换个小模型"
- 是否理解降本手段的**优先级和 trade-off**(效果 vs 成本 vs 延迟 vs 体验)
- 能否给出分阶段落地方案,并说明如何验证降本不显著伤害核心业务指标

## 参考答案

**一句话核心**:先**定位成本暴涨的根因**,再按"无损降本 → 低损降本 → 结构性优化"三层递进,绝不一上来就砍模型能力。

### 第一步:成本诊断(先算账再动手)

```
总成本 = 请求量 × 单次请求成本
单次请求成本 = f(模型单价, 输入token, 输出token, 是否走RAG/Agent多步调用)
```

**先回答三个问题**:

| 诊断问题 | 常见发现 |
|----------|----------|
| 量涨了还是单价涨了? | 功能上线后 DAU 渗透率高,请求量 ×8;或 Agent 多轮调用导致单次请求 token 暴增 |
| 哪类请求最贵? | 长尾 20% 的复杂请求占了 80% 的成本 |
| 效果冗余在哪? | 简单分类/提取任务用了旗舰模型,大材小用 |

**产出**:一张成本分布图——按功能、按用户层级、按请求复杂度拆分,确定优化靶点。

### 第二步:三层降本策略

#### 第一层:无损降本(优先做,效果基本不变)

| 手段 | 原理 | 预期降幅 |
|------|------|----------|
| Prompt 压缩 | 精简系统 Prompt,压缩历史上下文(滑动窗口/摘要) | 20-40% |
| 缓存 | 相同/相似 query 命中缓存,跳过模型调用 | 20-50%(视重复率) |
| 批处理 | 非实时任务合并请求,降低 API 开销 | 10-20% |
| 输出长度限制 | max_tokens 约束,避免冗长回复 | 10-30% |

#### 第二层:低损降本(需 A/B 验证)

| 手段 | 原理 | 风险 |
|------|------|------|
| 模型分级路由 | 简单 query → 小模型,复杂 query → 大模型 | 路由误判导致效果下降 |
| 级联调用 | 先用便宜模型,置信度低再升级 | 延迟略增 |
| 减少 Agent 步数 | 合并工具调用,减少多轮推理 | 复杂任务成功率可能降 |
| 蒸馏/微调小模型 | 用大模型生成数据,训练专用小模型 | 前期投入大,长期划算 |

**模型路由示意**:

```
用户请求 → 意图分类(极小模型,几乎零成本)
  ├── 简单(70%) → 小模型处理
  ├── 中等(25%) → 中模型处理
  └── 复杂(5%)  → 大模型处理
```

#### 第三层:结构性优化(产品 + 商业层面)

| 手段 | 说明 |
|------|------|
| 功能分层 | 免费用户限次/限模型,付费用户全功能 |
| 异步化 | 非实时场景改为后台处理,可用更便宜算力 |
| 自部署开源模型 | 日请求量足够大时,自部署 DeepSeek/Llama 等可能低于 API |
| 重新评估功能必要性 | 是否所有场景都需要 LLM?规则 + 模板能解决的不要上模型 |

### 第三步:落地节奏

| 阶段 | 时间 | 动作 | 验证 |
|------|------|------|------|
| 第 1 周 | 诊断 | 成本归因,确定 Top 3 优化点 | 成本分布报告 |
| 第 2-3 周 | 快赢 | Prompt 压缩 + 缓存 + 输出限制 | 成本降 30-50%,核心指标不降 |
| 第 4-6 周 | 路由 | 上线模型分级,灰度验证 | A/B:效果损失 < 2%,成本再降 30% |
| 第 2-3 月 | 结构 | 评估自部署/蒸馏,功能分层 | 总成本降 70-90% |

### 第四步:向老板汇报的框架

> "成本涨 10 倍的原因主要是 [请求量涨 X 倍 + 单次成本涨 Y 倍]。我计划分三步:
> 1. 两周内通过 Prompt 优化和缓存降 40%,不影响用户体验;
> 2. 一个月内上线模型路由,再降 30%,核心指标波动控制在 2% 以内;
> 3. 季度内评估自部署,目标总成本回到涨前水平的 1.5 倍以内(功能多了,完全回到原水平不现实)。"

## 追问延伸

- **追问 1**:"模型路由如果误判了,把复杂问题发给小模型,用户体验崩了怎么办?"
  → 设 fallback 机制:小模型置信度低或用户点"不满意"时自动升级;监控路由准确率,持续优化分类器。
- **追问 2**:"业务方说不能降效果,只要降本,你怎么办?"
  → 用数据说话:列出每个优化手段的效果损失预估(通常无损手段就能降 40-50%);若仍不够,讨论功能分层或商业定价,把成本转嫁给愿意付费的用户。
- **追问 3**:"缓存会不会导致回答过时?"
  → 区分场景:FAQ、政策解读等稳定内容适合缓存;实时信息(股价、天气)不缓存或短 TTL;产品侧标注"回答时间"增加信任。
