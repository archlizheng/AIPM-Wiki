# JD 写「熟悉大模型」，面试官的三档标准是什么？怎么自测？

**难度**:⭐⭐ 常规
**出现频率**:高,几乎每个 AI PM JD 都会写「熟悉大模型 / LLM」,技术面常用它开场定档

## 考察点

- 能否把模糊的「熟悉」拆成**可验证行为**,而不是背术语表
- 是否诚实自报档位,并用项目证据支撑,而不是把「调过 API」写成「深度熟悉」
- 面对「为什么不用大模型 / 为什么不用更强模型」时,能否用约束与取舍回答

## 参考答案

### 一句话核心

面试官心里通常有三档:**概念可用(L1)** → **方案可判(L2)** → **选型可辩(L3)**。JD 的「熟悉」几乎没有信息量;你要先定自己的真实档位,再用一页证据自报家门。完整行为表与升档动作见正课 [能力模型 · 「熟悉大模型」三档自评](../../00-roadmap/ai-pm-capability-model.md#六熟悉大模型三档自评)。

### 三档标准(面试官听什么)

| 档位 | 面试官想听到的 | 一句话自报示范 | 常见扣分 |
|------|----------------|----------------|----------|
| **L1 · 概念可用** | 大模型擅长/不擅长什么;token、上下文、温度对体验意味着什么;亲手调过主流 API/控制台 | 「我能讲清边界并亲手跑通过 API,选型细节还要和算法一起判」 | 只会背幻觉/token,说不出对产品设计的含义 |
| **L2 · 方案可判** | 用 PM 语言讲 Transformer/注意力对长文本、延迟、成本的含义(不必推公式);能在 Prompt / RAG / 微调 / Agent / 不上 AI 之间给初判 | 「给我场景,我能先排候选路径并写清放弃理由,再用小样本对照」 | 「都试一下」「听算法的」「效果更好」四字选型 |
| **L3 · 选型可辩** | 从业务目标倒推效果底线、延迟、成本、合规;能平等讨论候选与取舍;「为什么不用大模型」同样有依据 | 「约束清楚后,我能带着评测/成本/风险证据进选型会」 | 只会站队「最强模型」或「必须自研」,被追问拿不出证据 |

**岗位目标档位不同**:多数应用型 AI PM 把 L2 做稳通常够用;模型厂商 / 平台岗更常考到 L3。岗位差异见 [AI PM 岗位类型盘点](../../00-roadmap/ai-pm-job-types.md)。

### 怎么自测(面试前 30 分钟可做)

**第一关 · 过没过 L2**

研发说「这个需求不适合用大模型」。若你只能点头或反问「那还能不能做」,多半还在 L1。若能立刻追出第二层原因并改方案,通常已跨过 L2:

- 是**延迟**扛不住,还是峰值下推理排队?
- 是**单位任务成本**算不过来,还是可以分级路由 / 缓存?
- 是**数据**不够 / 分布漂移 / 标注差,还是任务本身更适合规则或小模型?
- 是**合规 / 可审计**硬约束,还是效果波动用户不可接受?

能把「不适合」拆成可验证约束,就是在用产品语言管理模型能力。

**第二关 · 有没有 L3 证据包**

任选一个真实场景,检查你能否在 5 分钟内讲清四栏:**约束 / 候选 / 取舍 / 复盘**。若只能讲「我们上了 GPT」,没有评测样本、成本粗算或放弃理由,先别在简历写「深度熟悉」。选型流程见 [模型选型决策框架](../../02-pm-skills/cost-and-tech/model-selection-framework.md)。

**第三关 · 简历措辞是否越档**

| 简历写法 | 更稳妥的改法 |
|----------|--------------|
| 「精通 / 深度熟悉大模型」但无选型证据 | 改成「能独立完成 Prompt/RAG 初判,参与过 X 次选型评审」 |
| 「熟悉 Transformer」只停在名词 | 补一句工程含义:长上下文 → 延迟/成本/截断风险 |
| 「主导模型选型」实际只提需求 | 改成「定义约束与验收标准,与算法共决候选」 |

### 面试怎么答(结构)

1. **先定档**:「按你们 JD 的『熟悉大模型』,我自评在 L2:能做方案初判,L3 的平等选型我还在用项目练。」诚实比虚高更安全。
2. **给一个场景证据**:目标 → 候选路径 → 为什么选/不选 → 用什么样本或指标验收。
3. **主动补边界**:「我不推公式,但我能把注意力机制翻译成长文本与成本约束;细节我会对齐算法同学。」

原理补课优先看 [Transformer 架构(PM 版)](../../01-ai-basics/llm/transformer-architecture.md);项目材料打包见 [项目深挖](project-deep-dive.md) 与 [作品集与 Demo](portfolio-and-demo.md)。

## 追问延伸

- **追问 1**:「你说熟悉大模型,讲讲 Transformer 对产品意味着什么?」
  → 不背公式:长依赖与上下文窗口如何影响截断、延迟、费用;注意力计算随序列变贵,为何长文档常要 RAG/分段而不是一次性塞满。细节链正课 Transformer 文。
- **追问 2**:「Prompt、RAG、微调、Agent,这个需求你怎么选?」
  → 先问失败可接受度、知识是否常变、是否多步工具调用、是否有标注预算;给出初判 + 放弃理由,而不是「都很好」。
- **追问 3**:「算法说必须用最强闭源模型,你怎么回应?」
  → 对齐业务底线与预算:用小样本对照效果差、延迟与单位成本;能分级路由就分级;坚持「最强」时要求写清不可替代的评测证据。
